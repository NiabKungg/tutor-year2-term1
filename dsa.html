ภาพรวมวิชา + ตาราง Big-O รวม

ผลลัพธ์การเรียน (CLO) ของวิชานี้

  • CLO-1 เข้าใจและใช้กระบวนการ abstraction ในการแก้ปัญหา
  • CLO-2 วิเคราะห์ทีละขั้นและพัฒนา algorithm แก้ปัญหาจริง
  • CLO-3 implement โครงสร้างข้อมูลและอัลกอริทึมพื้นฐาน
  • CLO-4 เข้าใจเทคนิค searching และ sorting ต่าง ๆ

ลำดับหัวข้อ: Introduction, Analysis, Array, Linked List, Stack/Queue, Recursion & Memoization, DP, Sorting, Heap & Priority Queue, BST, Adv. BST, Graph, Hashing

ADT และพื้นฐาน Java ที่ต้องรู้ (L01)

  • ADT (Abstract Data Type): โมเดลของชนิดข้อมูลที่สนใจ "ว่าทำอะไรได้" และ efficiency แต่ไม่สนว่า implement อย่างไร เช่น Stack, Queue, Heap, Tree, Graph
  • Data vs Information: data คือข้อมูลดิบ, information คือข้อมูลที่พร้อมใช้; basic operations คือ CRUD (Create, Retrieve, Update, Delete)
  • Class = blueprint, Object = instance; main เป็น static เพราะรันก่อนจะมี object ใด ๆ; เรียก static ผ่านชื่อ class เช่น Counter.add(2,3), เรียก instance ผ่านชื่อ object เช่น c.inc()
  • Reference & pass-by-value: primitive เก็บค่าจริง, object variable เก็บ reference; Java ส่งสำเนาของค่าเข้า method (สำหรับ object คือสำเนาของ reference) จึงแก้ข้างใน object เดิมได้ แต่ assign ตัวแปรใหม่ไม่มีผลกับผู้เรียก
  • เขียนแบบ "abstraction ซ้าย, implementation ขวา": List<String> names = new ArrayList<>();, Queue<Integer> q = new ArrayDeque<>();, Generics (<String>) ระบุชนิดข้อมูล
ประเด็นสำคัญ: เลือก collection ให้ตรงงาน
  • ArrayList: indexed sequence, get/set เร็ว แต่แทรก/ลบต้น ๆ ต้อง shift
  • HashSet: ไม่มีข้อมูลซ้ำ, contains/add/remove โดยปกติเร็ว, ไม่เรียงลำดับ
  • TreeMap: key เรียงลำดับ, put/get/remove ~O(log n), เหมาะกับ ordered lookup / range query
  • PriorityQueue: default ให้ตัวเล็กสุดก่อน, รับประกันแค่ poll() ได้ตัวที่ "ดีที่สุด" ไม่ได้เก็บเรียงทั้งก้อน
  • Comparator: ค่า negative/zero/positive หมายถึง มาก่อน/เท่ากัน/มาหลัง เช่น students.sort((a,b) -> a.score - b.score);

การวิเคราะห์อัลกอริทึม (L02)

  • ลักษณะของ DS/Algorithm ที่ดี: Correctness, Efficiency (Time/Space), Readability
  • Correctness พิสูจน์ได้ 2 ทาง: formal/mathematical proof (รับประกัน 100%: ทางตรง, ขัดแย้ง, contraposition, mathematical induction) และ empirical analysis (test) ที่ต้องมี test case ครบและระวัง confirmation bias
  • Efficiency วัดได้ 2 วิธี: Benchmark (เหมาะกับชิ้นงานจบแล้ว, ต้องคุม environment/hardware/language ให้เหมือนกัน; benchmark ที่ดี: Relevance, Representativeness, Equity, Repeatability, Cost-effectiveness, Scalability, Transparency) และ Asymptotic analysis (สนใจ growth rate เมื่อ n ใหญ่มาก, system-independent)
  • Operation counting: สมมติ 1 statement ใช้เวลาคงที่เท่ากัน เช่น int m = n/2; นับ 3 operations (declaration + assignment + division) แล้วสร้าง operation function ของโค้ด
ตัวอย่าง: นับ operation ของ isPrime 3 เวอร์ชัน
  1. f0(n) = 2n + 5 (isPrime0, loop วนถึง n/2 ครั้ง) ตัดพจน์คงที่และ coefficient เหลือ O(n)
  2. f1(n) = 4√n + 6 (isPrime1, loop วนถึง √n ครั้ง) เหลือ O(√n)
  3. f2(n) = 7√(n/6) + 15 (isPrime2, step ทีละ 6) ยังเป็น O(√n) เพราะ 1/√6 เป็นค่าคงที่
  4. สรุป: จำนวน operation ไม่ขึ้นกับเครื่อง จึงเทียบ algorithm กันโดยตรงได้ (isPrime1/isPrime2 เร็วกว่า isPrime0 มาก)

Asymptotic Notation

  • Big-O: g(n) เป็น upper bound ของ f(n), f โต "ไม่เร็วกว่า" g (ไม่แย่กว่า)
  • Big-Omega (Ω): g(n) เป็น lower bound, f โต "เร็วกว่า"/ไม่ดีกว่า g
  • Big-Theta (Θ): f และ g โต ด้วยอัตราเดียวกัน (tight bound)
  • เทียบด้วย limit ที่ n → ∞: lim f1/f2 = ค่าคงที่บวก → Θ; = ∞ → f1 ใหญ่กว่า (Ω); = 0 → f2 เล็กกว่า (O)
  • ในทางปฏิบัติ: คนมักพูด Big-O แต่คาดหวังค่าที่แคบที่สุด (เทียบเท่า Θ) เช่น 4√n + 6 ∈ O(n) ถูกทางเทคนิคแต่ที่คาดหวังคือ O(√n)
ตัวอย่าง: เทียบ growth rate ด้วย limit
  1. ให้ f(n) = 4n² + 3n + 4 และ g(n) = n²
  2. หารทุกพจน์ด้วย n²: f/g = 4 + 3/n + 4/n²
  3. เมื่อ n → ∞ ได้ limit = 4 (ค่าคงที่บวก)
  4. ตอบ: f โตด้วยอัตราเดียวกับ n² → f(n) ∈ Θ(n²)
  • O vs Θ จากโค้ด: ถ้ามี early exit (เช่น linearSearch) best case O(1), worst O(n), bound ต่างกันจึงรายงานด้วย O(n) (worst case); ถ้า ไม่มี early exit (เช่น findMax loop ต้องรันครบเสมอ) best = worst = Θ(n)
  • วิธีหา Big-O จากโค้ด: ดู most frequently executed line เช่น loop ใน partition (Lomuto/Hoare) วน ~N รอบ → O(N)

อ่านเพิ่ม: P vs NP
ปัญหาที่แก้ได้ใน polynomial O(nᵏ) อยู่ใน P class; NP-complete คือกลุ่มที่ยังไม่มี polynomial solution; ปัจจุบันยังไม่มีใครพิสูจน์ P ≠ NP
มักออกสอบ
  • นับ operation ของโค้ดสั้น ๆ แล้วสรุปเป็น Big-O
  • จำแนก O / Ω / Θ และอ่าน limit เทียบ growth rate
  • บอก best/worst/average ของโค้ดที่มี/ไม่มี early exit และเลือกใช้ O หรือ Θ ให้เหมาะ
  • หา Big-O ของ loop รูปแบบต่าง ๆ (i*=2, i=i², halving กับ linear inner)

Array (L03)

  • Array คือข้อมูลชนิดเดียวกันเรียง ติดกันใน memory (contiguous) อ้างด้วยชื่อเดียว; ใน Java array เป็น object อยู่ใน heap; byte[] b, d; ทำให้ทั้งคู่เป็น array แต่ byte a[], c; จะทำให้ c เป็นแค่ byte
  • Random access O(1): คำนวณจาก "ตำแหน่งเริ่มต้น + index" ได้โดยตรง; ควรห่อหุ้มด้วย getAt()/setAt() เพื่อควบคุมการเข้าถึง
  • add ไม่สนลำดับ: วางท้าย array เป็น O(1); ตรวจ error ด้วย isFull()/isEmpty() (O(1) ทั้งคู่) ได้ 3 แบบ: เช็คก่อนเรียก (v1) / เช็คใน method แล้ว return -1 หรือ boolean (v2) / throw exception (v3, ช้าสุด)
  • find ใน unordered: linear search, best O(1), worst/average O(n)
  • binarySearch ใน ordered: ตัดครึ่งทุกรอบ, worst O(log n), average ก็ O(log n)
// add ไม่สนลำดับ: วางท้าย
data[size++] = d;

// insert ลง unordered: ย้ายค่าเดิมที่ index ไปท้ายแล้ววางใหม่
data[size++] = data[index];
data[index] = d;

// insert ลง ordered: shift ข้อมูลที่มากกว่าไปทางขวา 1 ช่องแล้ววาง
for (int i = size; i > index; i--) data[i] = data[i-1];
data[index] = d;

// delete จาก unordered: ก๊อบตัวท้ายมาแทน จึงเป็น O(1)
data[index] = data[--size];
ตัวอย่าง: average case ของ ordered insert และจำนวนรอบของ binary search
  1. Ordered insert: แทรกที่ index ต้อง shift ได้ 1, 2, ..., n ช่อง รวม 1+2+...+n = n(n+1)/2
  2. หารด้วย n ตำแหน่ง: เฉลี่ย (n+1)/2 ช่อง → Average O(n) (best คือแทรกปลายทาง O(1), worst คือ index 0)
  3. Binary search: รอบที่ 1 เหลือ n, รอบที่ 2 เหลือ n/2, ..., รอบที่ k เหลือ 1
  4. k = log n + 1 รอบ → worst O(log n); average ก็ O(log n) (จาก Σ i·2^(i-1) = (k-1)2^k + 1)

ข้อจำกัด + Expanding Array

  • Array ขยายขนาดไม่ได้ และต้องการ memory ต่อเนื่อง: อาจมี memory เหลือพอแต่จอง block ใหญ่ไม่ได้
  • ทางแก้: สร้าง array ใหม่ → copy ทั้งหมด → ชี้ไปที่ใหม่ → เก่าถูก GC; expands() เองเป็น O(n) เสมอ; add with expand: best O(1), worst O(n)
  • Version A: MAX_SIZE = MAX_SIZE + M (เพิ่มคงที่): ต้นทุน copy สะสมเป็น arithmetic series = O(n²) รวม, เฉลี่ยต่อ insertion = O(n) (M เป็นแค่ constant factor)
  • Version B: MAX_SIZE = 2*MAX_SIZE (เท่าตัว): n = 2^k·S, ผลรวม operation = 2n − S → average/amortized O(1) ต่อ add เป็นตัวอย่างคลาสสิกของ amortized analysis
ตัวอย่าง: copy cost ของ expand แบบ +M (S=10, M=10, ใส่ 100 ตัว)
  1. เริ่มความจุ S = 10, ทุกครั้งที่เต็มจะขยายเพิ่ม M = 10: 10 → 20 → 30 → ... → 100 (expand 9 ครั้ง)
  2. copy cost แต่ละครั้ง = ขนาด array เดิม: 10 + 20 + 30 + ... + 90 = 450 writes
  3. total writes = 100 (insert เอง) + 450 (copy) = 550 writes
  4. ต้นทุน copy สะสมเป็น arithmetic series → รวม O(n²), เฉลี่ยต่อ add = O(n)

Linked List (L04)

  • เก็บข้อมูลเป็น node แยกกัน เชื่อมด้วย reference: node = data + next; ตัว list เก็บแค่ head (และ size); node สุดท้ายชี้ null
  • เก็บแบบ non-contiguous ได้ (ต่างจาก array) แต่ random access เป็น O(n) เพราะต้องเดินตาม next
  • Invariants: head == null → list ว่าง; ทุก node ยกเว้นตัวสุดท้ายชี้ node อื่น; เสีย head = เสียทั้ง chain
  • Traversal มาก่อนเสมอ: เช็ค p != null ก่อนใช้ p.data/p.next ทุกครั้ง
// traversal พื้นฐาน
Node p = head;
while (p != null) {
    // ทำงานกับ p.data
    p = p.next;
}

// insert ระหว่าง node: p = node ก่อนจุดแทรก, n = node ใหม่
n.next = p.next;   // ต่อ n เข้ากับส่วนท้ายเดิมก่อน (ไม่งั้นเสีย chain)
p.next = n;        // ค่อยเชื่อม p ไปที่ n

// insert ลง list ที่เรียงอยู่แล้ว (insertSort): เดินหา node "ก่อนจุดแทรก"
while (p.next != null && p.next.data < d) p = p.next;
n.next = p.next;
p.next = n;

// delete ต้องมี previous node
p.next = p.next.next;
ข้อผิดพลาดที่พบบ่อย
  • สลับลำดับคำสั่งเป็น p.next = n; ก่อน n.next = p.next; จะทำให้เสีย reference ไปหา node ถัดไป (chain ขาด)
  • ลบ head โดยลืมว่า head ไม่มี previous node ต้องแก้ด้วย dummy node
  • Operations: getAt(i)/setAt(i,d) เดิน i ครั้ง → O(i), worst O(n); addFirst(d): p.next = head; head = p; → O(1); addLast(d) เดินหา tail (ไม่มีตัวแปร tail) → O(n); find(d) sequential → average/worst O(n), isFound(d) = find(d) >= 0
  • Dummy node: สร้าง dummy นำหน้า head ชั่วคราว ทำให้ลบ head เหมือนลบ node ทั่วไป จบแล้วตั้ง head = dummy.next
  • Doubly linked list: node มี prev ด้วย, ไปหน้า/หลังได้ (undo/redo), ลบตำแหน่งที่รู้อยู่แล้วได้ O(1): p.next.prev = p.prev; p.prev.next = p.next;
  • Circular linked list: node สุดท้ายชี้กลับ node แรก (round-robin); deque (push_front/push_back/pop_front/pop_back) มัก implement ด้วย circular doubly linked list + sentinel/dummy node ช่วยให้โค้ดสะอาด
  • Edge cases checklist: list ว่าง, list มี node เดียว, add/delete ที่ head/tail, ค่าไม่พบ, ค่าซ้ำ, index ไม่ถูกต้อง

Stack (L05)

  • Stack = collection ที่ add/remove ที่ "top" ทางเดียว → LIFO (Last In, First Out)
  • Operations หลัก: push (ใส่), pop (หยิบ) ต้องเป็น O(1); สะดวกเพิ่ม: top/peek (มอง); utility: isFull, isEmpty, toString
  • Stack overflow = error เมื่อ push ลง stack ที่เต็ม
// MyStackA: array + ตัวแปร top
push:    stack[top++] = d;
pop:     return stack[--top];
top():   return stack[top-1];
isFull:  top == MAX_SIZE
isEmpty: top == 0

// MyStackL: linked list, push/pop ที่หัว
push:    p.next = top; top = p;        // เหมือน addFirst
pop:     d = top.data; top = top.next;
isFull:  return false;                 // ไม่มีขีดจำกัด
isEmpty: top == null
  • Lab: MyStack<T> ต้อง ห่อ (wrap) ArrayList ไม่ใช่ extends: push = items.add, pop = items.remove(size-1), peek = items.get(size-1)
  • Decimal → Binary: หาร 2 เก็บเศษใส่ stack แล้ว pop ออกมาพิมพ์ ได้บิตจากหลังไปหน้าโดยไม่ต้อง reverse (decimal >>= 1 ก็คือหาร 2)
  • RPN (postfix): เขียน operator หลัง operand เช่น 3 * (10 + 5) → 3 10 5 + *; Polish (prefix) เก่ากว่า ของ Jan Łukasiewicz (1924), RPN (1954); postfix/prefix ไม่ต้องใช้วงเล็บ (expression tree)
  • คิดค่า RPN ด้วย stack หนึ่งอัน: token เป็นเลข → push; เป็น operator → b = pop(); a = pop(); push(a opr b); จบแล้วต้องเหลือค่าเดียวใน stack
  • Infix → Postfix แบบ visual: (1) ใส่วงเล็บครบตาม precedence (2) ย้าย operator ไปขวาของ operand คู่นั้นแล้วตัดวงเล็บ; only infix needs parentheses
ตัวอย่าง: คิดค่า RPN "8 5 - 4 2 + 3 / *" ด้วย stack
  1. push 8 → [8], push 5 → [8, 5]
  2. เจอ "-": b = 5, a = 8 → push 8 - 5 = 3 → [3]
  3. push 4 → [3, 4], push 2 → [3, 4, 2]
  4. เจอ "+": b = 2, a = 4 → push 4 + 2 = 6 → [3, 6]
  5. push 3 → [3, 6, 3]
  6. เจอ "/": b = 3, a = 6 → push 6 / 3 = 2 → [2]
  7. เจอ "*": b = 2, a = 3 → push 3 × 2 = 6 → [6]
  8. จบ token เหลือค่าเดียว = 6
ตัวอย่าง: แปลง infix → postfix ด้วยวิธีใส่วงเล็บ (A + B * C)
  1. ใส่วงเล็บครบตาม precedence: (A + (B * C))
  2. ย้าย operator ไปขวาของ operand คู่: (B * C) → B C *
  3. ชั้นนอก: (A + B C *) → A B C * +
  4. ตอบ: A B C * +
อ่านเพิ่ม: Example challenge Leetcode 20 Valid Parentheses
เมื่อเจอวงเล็บเปิด ให้ push "วงเล็บปิดที่คาดหวัง" ลง stack แล้วเช็คว่าตอนเจอวงเล็บปิด pop ออกมาตรงกับตัวที่เจอ
มักออกสอบ
  • push/pop/top ทั้งสอง implementation ต้อง O(1) และเขียนโค้ดได้
  • trace การคิดค่า RPN ทีละ token (สถานะ stack)
  • แปลง infix → postfix ด้วยวิธีใส่วงเล็บ
  • เงื่อนไขสำคัญ: ต้องกลับลำดับ a, b ให้ถูกสำหรับ operator "-" และ "/"

Queue (L06)

  • Queue = คิวจริง ๆ: เข้าหาง ออกหัว → FIFO (First In, First Out)
  • Operations: enqueue (เข้าท้าย), dequeue (ออกหัว) ต้องเป็น O(1); nice-to-have: front; utility: isFull/isEmpty/toString
// MyQueueL: linked list ต้องมีทั้ง head และ tail
enqueue: tail.next = p; tail = tail.next;   // ต่อท้าย O(1)
dequeue: d = head.data; head = head.next;   // หั่นหัว O(1)
isFull:  return false;
isEmpty: head == null
// edge case: ถ้า dequeue จน head = null ต้องตั้ง tail ด้วย

// Circular array: เลื่อน index แบบวนกลับ
enqueue: queue[tail] = d; tail = (tail + 1) % MAX_SIZE;
dequeue: d = queue[head]; head = (head + 1) % MAX_SIZE;
isFull:  ((tail + 1) % MAX_SIZE) == head   // เว้นช่องว่าง 1 ช่อง
isEmpty: head == tail
  • Array ธรรมดาที่ dequeue แบบขยับทั้งแถวเป็น O(n) → แก้ด้วย circular array; การเว้นช่องว่าง 1 ช่องเป็นวิธีแยกสภาวะ "เต็ม" ออกจาก "ว่าง" (empty คือ head == tail)
  • ถ้า linked-list queue ไม่มี tail enqueue จะต้องเดินหาท้ายกลายเป็น O(n)

Shunting-yard Algorithm (Dijkstra, 1961)

  • แปลง infix → postfix โดยใช้ queue เป็น output + stack เก็บ operator
เลข       -> enqueue เข้า queue
operator  -> pop operator บน stack ที่มี precedence มากกว่าหรือเท่ากับ
             ออกไปก่อน แล้ว push ตัวปัจจุบัน
(         -> push ลง stack
)         -> pop จนเจอ ( แล้วทิ้งวงเล็บทั้งคู่
จบ token  -> pop ที่เหลือทั้งหมดเข้า queue
ตัวอย่าง: shunting-yard กับ "3 + 4 * ( 7 - 5 )"
  1. 3 → queue: [3]
  2. + → stack ว่าง push: stack [+]
  3. 4 → queue: [3, 4]
  4. * → precedence มากกว่า + → push: stack [+, *]
  5. ( → push: stack [+, *, (]
  6. 7 → queue: [3, 4, 7]
  7. - → top เป็น ( → push: stack [+, *, (, -]
  8. 5 → queue: [3, 4, 7, 5]
  9. ) → pop จนเจอ (: นำ - ออกเข้า queue แล้วทิ้ง ( → queue: [3, 4, 7, 5, -]
  10. จบ token: pop ที่เหลือทั้งหมด ตอบ: 3 4 7 5 - * +
  • วิเคราะห์ complexity: n tokens → n รอบ, ทุก operator เข้า/ออก stack รอบละครั้ง → O(n)
  • สายการผลิตคำนวณสมการ: infix → (shunting-yard) → postfix → (RPN evaluation ด้วย stack) → ค่าตอบ ทั้งหมด O(n)
  • Queue กับ BFS: Flood Fill และ Exit detection ใน grid ใช้ Queue (BFS) เดิน 4 ทิศ พร้อม visited/เช็คสีปลายทางกันเดินวน
  • Lab queue ใช้ enqueue(T), dequeue(), peek(), isEmpty(), iterator() และเรียกด้วยคำว่า front/back ไม่ใช่ top/bottom
ตัวอย่าง: คำนวณสมการครบวงจร (lab) "( 4 + 2 ) / 3 * ( 8 - 5 )"
  1. Shunting-yard แปลงเป็น postfix: 4 2 + 3 / 8 5 - *
  2. RPN evaluation: 4 + 2 = 6 → 6 / 3 = 2 → 8 - 5 = 3 → 2 × 3 = 6
มักออกสอบ
  • เงื่อนไข full/empty ของ circular array (ออกบ่อย)
  • ทำไม linked-list queue ต้องมี tail (ไม่งั้น enqueue เป็น O(n))
  • แปลง infix → postfix ด้วย shunting-yard และบอกบทบาท stack/queue
  • complexity รวม infix → postfix → ค่าตอบ = O(n)

Recursion, DP และ Divide & Conquer

Part 1: Recursion

  • นิยาม: แก้ปัญหาโดยเรียก method เดิมกับปัญหาที่ เล็กลง; ต้องมี base case และ progress เข้าหา base case ทุก call ไม่งั้นเกิด infinite/stack overflow
  • 3 คำถามหลัก: State (พารามิเตอร์ใดบรรยาย subproblem), Recurrence (state นี้พึ่ง state เล็กกว่าอย่างไร), Base case (state ใดตอบได้ทันที)
  • Factorial: n! = 1 if n=0; (n-1)! * n if n>0: Time O(n), Memory O(n) เพราะ call รออยู่บน stack
  • ชนิด recursion: single (factorial, เรียกตัวเองครั้งเดียว) vs multiple (fibonacci); recursion เขียนด้วย stack แทนได้; tail recursion เขียนเป็น loop แทนได้; ตัวอย่าง GCD แบบ Euclidean
  • Subset generation (decision-tree recursion): ที่ position i เลือก "ใส่/ไม่ใส่" A[i] → candidate space 2ⁿ; ใช้เทคนิค backtracking: include → recurse → undo (deleteCharAt/เคลียร์ค่า) → exclude → recurse; ห้ามสร้าง placeholder ใหม่ทุก call ต้องเปลี่ยน state ของตัวเดิม
  • Permutation: loop หาตัวที่ยังไม่ใช้ (used[i]), choose → explore → un-choose; รวม n! แบบ
  • C(n,k) / P(n,k): ปรับ base case เป็น ele.size() == k (หรือ level == k) + pruning ถ้าเหลือตัวไม่พอ
long fact(int n) {
    if (n == 0) return 1;      // base case
    return fact(n - 1) * n;    // progress: ปัญหาเล็กลงทุก call
}
  • Algorithm Paradigms: Brute Force (ลองทุก candidate), Decrease & Conquer (ลดทีละปัญหาเดียว: by one = factorial, by constant = insertion sort, by factor = binary search), Divide & Conquer (แบ่งเป็น subproblem อิสระ เช่น Merge Sort), DP (reuse คำตอบ subproblem ที่ซ้ำ), Greedy, Transform & Conquer, Backtracking/Branch-and-Bound
  • กุญแจ: DP ต้องมี repeated states; D&C ต้องมี independent branches

Fibonacci: Memoization → DP

  • Naive fib: F(n) = F(n-1) + F(n-2) เป็น exponential O(2ⁿ) เพราะ subproblem (เช่น fib(3), fib(2)) ถูกคำนวณซ้ำ ๆ ทั้งที่มีแค่ n+1 states
  • Memoization (Top-Down DP): เก็บคำตอบใน memo[], เจอซ้ำตอบทันที → Time O(n), Memory O(n) โครง recursion ยังอยู่; top-down อาจ cache miss = ดี เพราะไม่คำนวณ state ที่ไม่จำเป็น
  • Bottom-Up DP: เลิก recursion ไปเติมตารางตาม dependency order (เล็ก → ใหญ่) เติมทุกช่อง
  • Space optimization: Fibonacci ต้องการแค่ 2 ค่าก่อนหน้า → O(1) space (ตัวแปร n_2, n_1, my_fib)
  • ขั้นออกแบบ DP: (1) นิยาม state (2) เขียน recurrence (3) base cases (4) เลือกลำดับประเมิน top-down/bottom-up (5) เช็ค complexity = (#states) × (งานต่อ state)
// Memoization (top-down)
long fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];   // เจอซ้ำ ตอบทันที
    return memo[n] = fib(n-1) + fib(n-2);
}

// Bottom-up DP
dp[0] = 0; dp[1] = 1;
for (int i = 2; i <= n; i++)
    dp[i] = dp[i-1] + dp[i-2];

ชุดตัวอย่าง DP

ตัวอย่าง: 1D Counting, Count Ways ก้าว 1, 3, 4 จนถึง N = 8
  1. Recurrence: ways[i] = ways[i-1] + ways[i-3] + ways[i-4] (เฉพาะ i-step ≥ 0), base ways[0] = 1 (ยืนนิ่ง 1 วิธี)
  2. ways[1] = 1, ways[2] = 1
  3. ways[3] = ways[2] + ways[0] = 1 + 1 = 2
  4. ways[4] = ways[3] + ways[1] + ways[0] = 2 + 1 + 1 = 4
  5. เติมต่อ: ตาราง i = 0..8 ได้ 1, 1, 1, 2, 4, 6, 9, 15, 25
  6. ways[8] = ways[7] + ways[5] + ways[4] = 15 + 6 + 4 = 25 วิธี; O(N) time/memory
ตัวอย่าง: 1D Optimization, House Robber (งับบ้านติดกันไม่ได้)
  1. Recurrence: dp[i] = max(skip = dp[i-1], take = money[i] + dp[i-2]); base dp[0] = money[0], dp[1] = max(money[0], money[1])
  2. ให้ money = 2, 7, 9, 3, 1: dp[0] = 2, dp[1] = max(2, 7) = 7
  3. dp[2] = max(7, 9 + 2) = 11, dp[3] = max(11, 3 + 7) = 11, dp[4] = max(11, 1 + 11) = 12
  4. dp = 2, 7, 11, 11, 12 → ตอบ 12 (เลือกบ้าน 0, 2, 4); ปรับ space เหลือ 2 ตัวแปรได้
  • Target-table DP, Subset Sum: T[i][j] = "ใช้ item 0..i ทำ sum j ได้ไหม"; transition = T[i-1][j] (skip) OR T[i-1][j-x] (use); base T[i][0] = true; ยุบเป็น 1D ได้โดย loop j จากหลังมาหน้า (B → x) เพื่อไม่ให้ใช้ x ซ้ำ
  • 2D Counting, Unique Paths: robot เดินขวา/ลง: dp[r][c] = dp[r-1][c] + dp[r][c-1] (ระวัง out-of-bound); ทำ bottom-up ย้อนจากปลายทางก็ได้ (symmetric); O(mn)
  • 2D Optimization, Min Path Sum: dp[r][c] = cost[r][c] + min(dp[r-1][c], dp[r][c-1]); O(mn)
  • Rod Cutting: dp[i] = max(price[j-1] + dp[i-j]) for j = 1..i; O(n²) time, O(n) memory (ขายความยาวซ้ำได้)
  • DP ใช้จริง: Unix diff (LCS), Viterbi, Smith-Waterman, Bellman-Ford, CKY; แพตเทิร์นร่วม: "ปัญหาใหญ่ประกอบด้วยปัญหาเล็กที่ซ้ำกัน"

Part 2: Divide & Conquer

  • 3 ขั้น: Divide (แบ่ง) → Conquer (แก้ subproblem, recursive จน base case) → Combine (รวมคำตอบ)
  • findMax: แบ่งครึ่ง หา max แต่ละฝั่ง เทียบกัน, recurrence T(n) = 2T(n/2) + O(1)
  • Maximum Subarray (subarray = ต่อเนื่อง ต่างจาก subset ที่เลือก/ไม่เลือกอิสระ): brute force มี n(n+1)/2 candidates = O(n²); แนว D&C คำตอบอยู่ได้ 3 แบบ: leftBest, rightBest, crossBest
  • crossBest ต้องคลุมกลาง: = max suffix ของครึ่งซ้าย (จบที่ mid) + max prefix ของครึ่งขวา (เริ่มที่ mid+1) หาด้วยการ scan สองทาง O(n)
  • recurrence T(n) = 2T(n/2) + O(n) → O(n log n) (log n ระดับ × งาน O(n) ต่อระดับ)
ตัวอย่าง: trace D&C Max Subarray 2 กรณี
  1. [4, -1, 2, -7, 5, 3]: leftBest ไม่ชนะ, crossBest = 6, rightBest = 8 (จาก [5, 3]) → ตอบ 8
  2. [-2, -5, 6, -2, -3, 1, 5, -6]: LB = 6, RB = 6, CB = 7 (max suffix ฝั่งซ้าย = 4 จาก [6, -2], max prefix ฝั่งขวา = 3 จาก [-3, 1, 5]) → crossBest ชนะ ตอบ 7
ตัวอย่าง: DP view ของ Max Subarray (Kadane)
  1. Recurrence: B[i] = max(B[i-1] + A[i], A[i]) (ต่อยู่ vs เริ่มใหม่ที่ i), ตอบ = max(B)
  2. A = [1, -5, 2, -1, 3]: B[0] = 1, B[1] = max(1-5, -5) = -4, B[2] = max(-4+2, 2) = 2, B[3] = max(2-1, -1) = 1, B[4] = max(1+3, 3) = 4
  3. B = 1, -4, 2, 1, 4 → ตอบ 4; Kadane เก็บแค่ 2 ตัวแปร → O(n) time, O(1) space

Recurrence Analysis + Master Theorem

  • วิธีวิเคราะห์: iteration/expansion, recursion tree, substitution (ไม่สอน), Master Theorem
  • T(n) = T(n/2) + Θ(1) → Θ(log n) (binary search); T(n) = 2T(n/2) + Θ(n) → Θ(n log n) (merge sort)
  • Recursion tree ของ T(n) = 2T(n/2) + n: ทุกระดับมีงาน Θ(n), มี Θ(log n) ระดับ
  • iteration method = การ expand recurrence ออกไปเรื่อย ๆ แล้วหา pattern

  • ทำไม naive fib เป็น O(2ⁿ) และ memoization ช่วยให้เหลือ O(n) time / O(n) memory

  • 3 cases ของ D&C max subarray, วิธีหา crossBest และ Kadane

  • ความต่าง DP กับ D&C: repeated states vs independent branches

Sorting (L08)

  • เหตุผลของการ sort: ทำให้ search/merge มีประสิทธิภาพ และ process ข้อมูลตามลำดับที่กำหนด
  • Comparison-based sort ที่ดีที่สุดได้ O(n log n) (แต่ละการจัดวางตรวจได้ O(n), ต้องเทียบอย่างน้อย O(log n) ครั้ง)
  • Internal/in-place sort = ไม่ต้องใช้ memory เพิ่ม (space O(1))
  • Stable sort = ข้อมูลที่ key เท่ากัน ไม่สลับลำดับเดิม จำเป็นเมื่อ sort ซ้อนหลาย key (primary/secondary)
  • ตัวชี้วัดแยกเป็น 2 อย่าง: จำนวนเทียบ (comparisons) กับ จำนวนสลับ (swaps)

  • วิธีทำ counting sort (prefix sum, ทิศทางการวาง)

Priority Queue และ Heap (L09)

  • Priority Queue: ADT ที่ element มี priority, ตัว priority สูงถูก serve ก่อน; ถ้า priority เท่ากันบาง implementation ก็ FIFO (แต่ heap ไม่รับประกัน FIFO ในกรณี priority เท่ากัน)
  • ไม่สน internal structure สนแค่ลำดับ dequeue ตาม priority
  • การใช้งาน: OS scheduling, interrupt handling, graph algorithm (Dijkstra/Prim/Huffman), load balancing, router, customer service
  • Implement ด้วย array/linked list ได้แต่ไม่ optimal → binary heap เป็นมาตรฐาน (มี binomial/Fibonacci heap ที่ดีกว่าเชิง amortized แต่เกินขอบเขต)

Binary Tree ศัพท์ที่เกี่ยว + Heap Property

  • Perfect: internal ทุก node มี 2 ลูก, leaf อยู่ระดับเดียวกัน
  • Complete: ทุกระดับเต็มยกเว้นระดับสุดท้าย และ leaf เอียงซ้าย
  • Balanced: height เป็น O(log n) (ต่าง height ซ้ายขวาไม่เกิน 1); (Full = ทุก node มี 0 หรือ 2 ลูก)
  • Heap property: max heap คือ parent ≥ ลูก, min heap คือ parent ≤ ลูก; root คือค่าสุดขีด

Array Representation + Operations

  • Heap เป็น complete tree จึงเก็บใน array ได้: ลูกซ้าย = 2p+1, ลูกขวา = 2p+2, parent = (p-1)/2
  • insert(d) O(log n): วางที่ตำแหน่งสุดท้าย (p = size++) แล้ว percolate up สลับกับ parent ในขณะที่ heap[p] < heap[parent] (min heap); สลับได้ไม่เกินความสูงต้นไม้
  • remove() O(log n): เอา root ออก (d = heap[0]), ยกตัวสุดท้ายขึ้นมาแทน (heap[0] = heap[--size]) แล้ว percolate down: เลือกลูกที่ "ดีที่สุด" (min heap → ลูกที่น้อยกว่า) มาสลับจนถึงดุล; จบด้วยเคส: ไม่มีลูก / ลูกเดียว / สองลูก
  • Heapify: แทรก n ครั้งทีละตัว = O(n log n); แต่ heapify ทั้ง array จากล่างขึ้นบน = O(n) เพราะ node ส่วนใหญ่อยู่ตื้น
  • Heap sort: ดึง root (poll) ซ้ำจนหมด → ได้ลำดับเรียง O(n log n)
  • Java PriorityQueue default = min-heap; ใช้ Comparator ถ้าต้องการกลับเกณฑ์
  • Lab: MyPQueue เป็น wrapper ของ MyMinHeap: enqueue → heap.insert, dequeue → heap.remove, front → heap.peek
// min heap: insert ท้ายแล้ว percolate up
heap[p = size++] = d;
while (p > 0 && heap[p] < heap[(p-1)/2]) {
    swap(heap[p], heap[(p-1)/2]);
    p = (p-1)/2;
}
อ่านเพิ่ม: มุมสนุกเรื่อง swap
สลับค่าได้หลายแบบ: ใช้ +/-, ใช้ ×/÷ หรือใช้ XOR แต่ต้องระวังกรณี overflow ของตัวเลข
มักออกสอบ
  • สูตร index ลูก/พ่อ และ trace insert/remove ทีละขั้น (วาด array)
  • O(log n) ของ insert/remove เพราะสลับไม่เกินความสูง
  • heapify O(n) กับแทรกสะสม O(n log n) ต่างกันอย่างไร
  • heap ไม่การันตี FIFO เมื่อ priority เท่ากัน (และคิดวิธีแก้)
  • Example challenge: Kth Largest จาก stream (maintain heap ขนาด k)

Binary Search Tree (L10)

  • Tree: ADT ที่ข้อมูลเชื่อมแบบต้นไม้; Root (reference หัวต้นไม้), Node (data + links ลูก บางที parent), Parent/children/ancestor, Siblings, Leaf (ไม่มีลูก), Depth ของ node = จำนวน edge จาก root, Height ของ tree = depth มากสุด, Subtree
  • Balance: ถ้า balance แล้ว height = O(log n); ถ้าบิดเบี้ยว (deformed) height เข้าใกล้ O(n) เคสแย่สุดคือกลายเป็น linked list
  • Representation: heap ใช้ array ได้เพราะ complete; ทั่วไปใช้ Node + references (TreeNode { int data; TreeNode left, right; })
  • Traversal: สถานะ node มี 3 แบบ: undiscovered, discovered, processed; binary tree มี 3 ลำดับ เขียน recursive ง่าย ๆ (เช็ค node == null แล้ว return)
  • Pre-order: Root → Left → Right
  • In-order: Left → Root → Right (ใช้ได้กับ binary tree เท่านั้น) บน BST จะได้ ลำดับเรียง
  • Post-order: Left → Right → Root
ตัวอย่าง: traversal ของ binary tree เล็ก ๆ
  1. Tree: root 2, ลูกซ้าย 1, ลูกขวา 3
  2. Pre-order (Root-L-R): 2, 1, 3
  3. In-order (L-Root-R): 1, 2, 3
  4. Post-order (L-R-Root): 1, 3, 2
  • BST property: ที่ทุก node ค่าของ node ไม่น้อยกว่าลูกซ้าย และ ไม่มากกว่าลูกขวา → binary search ทำได้; search/insert/delete O(log n) เมื่อ balance, O(n) เมื่อบิดเบี้ยว
  • insert(d): เดินจาก root เทียบค่าไปซ้าย/ขวาจนช่องว่าง แล้วผูก node ใหม่ (ตั้ง parent ด้วย); มีทั้งแบบ iterative (while) และ recursive (searchRecurse)
  • findMax: เดิน right จนสุด

// อีกแนว: swap ค่า candidate เข้า node แล้วลบ candidate ที่ตำแหน่งเดิม
  • delete(d) 3 เคส: (1) Leaf: ตัดออกเลย (2) One-child: แทนที่ด้วยลูกของมัน (3) Two-children: แทนที่ด้วย ค่ามากสุดใน left subtree (predecessor) หรือ ค่าน้อยสุดใน right subtree (successor) เพื่อรักษา BST property ทั้งสองฝั่ง
ตัวอย่าง: rangeSumBST รวมค่าในช่วง [low, high]
  1. ถ้า node < low → เดินขวาอย่างเดียว; ถ้า node > high → เดินซ้ายอย่างเดียว (pruning)
  2. ถ้าอยู่ในช่วง → รวมค่า + recurse ทั้งสองฝั่ง
  3. Trace จากสไลด์: BST root 5, ค้นช่วง [4, 8] → ได้ 4 + 5 + 7 + 8 = 24
มักออกสอบ

  • delete 3 เคส โดยเฉพาะ two-children: ใครมาแทน และทำไม
  • ผลของการ insert ลำดับเรียงแล้วได้ deformed tree → O(n)
  • depth/height/sibling/leaf: นิยาม + หาค่าจากรูป
  • โครงสร้าง TreeNode ที่มี parent pointer และเหตุผล

Advanced Tree: AVL, Red-Black, Splay (L11)

3 กลยุทธ์ทำให้ BST balance: balance เป๊ะ (sort ก่อนสร้าง), balance พอประมาณ (AVL, Red-Black), ยก node ที่เพิ่งใช้ขึ้นบน (Splay)

AVL Tree

  • นิยาม: height ของ left/right subtree ต่างกันได้ ไม่เกิน 1 เก็บ height ซ้าย/ขวาไว้ที่ node (bookkeeping)
  • balance factor = h_left − h_right (ซ้ายหนักเป็นบวก, ขวาหนักเป็นลบ; empty = -1, leaf h = 0)
  • ความสูงว่ายังไงก็ h < 1.44·log₂n เรียกว่า "pretty balance"
  • Rotation 4 แบบ: single: RR imbalance → Left rotation, LL imbalance → Right rotation; double: LR imbalance (หมุนซ้ายก่อนแล้วขวา), RL imbalance (หมุนขวาก่อนแล้วซ้าย)
  • Insert: ancestor อาจมี BF = ±2 → ไต่ขึ้นหา unbalance node แล้วหมุน, หมุนได้มากสุด 1 ครั้ง; ต้อง recompute height ทุกครั้งหลัง insert/delete/rotate เพื่อให้ height() เป็น O(1)
  • Delete: ยุ่งกว่า insert อาจต้อง rotate/double-rotate ที่ node และ ancestors ต่อเนื่อง หมุนได้ถึง ~1.44 log₂n ครั้ง + อัปเดต height/BF ตลอดเส้นทาง
  • ต้นทุน: insert/delete/access O(log n) แต่ค่าคงที่แพง
  • Parent pointer: มี → ไต่ขึ้นง่าย (successor/predecessor/transplant, iterator) แต่ memory เพิ่ม + rotation ต้องอัปเดต parent เยอะ bug-prone; ไม่มี → โค้ดสะอาด; AVL นิยมแบบไม่มี parent, Red-Black (TreeMap) นิยมมี parent
// recompute height ให้เป็น O(1) เสมอ
n.height = 1 + max(height(n.left), height(n.right));

// เงื่อนไขหมุนของ delete (ฝั่งซ้ายหนัก, bf = balance factor)
if (bf(n) > 1 && bf(n.left) >= 0)      rightRotate(n);                       // LL
if (bf(n) > 1 && bf(n.left) < 0)       { leftRotate(n.left); rightRotate(n); } // LR
// ฝั่งขวาหนักทำสมมาตรกัน (RR, RL)

Red-Black Tree

  • Invariants 5 ข้อ: (1) เป็น BST (2) ทุก node มีสี red/black (3) root เป็น black (4) node red ต้องมีลูก black ทั้งคู่ (ห้าม red ติดกัน) (5) ทุก path จาก node ลง NIL มีจำนวน black เท่ากัน (black-height เท่ากัน); NIL leaf ถือเป็น black
  • path ยาว/สั้นต่างกันได้ (ยาวสุด B-R-B-R-...B) แต่ black-height เท่ากัน
  • Height bound: longest ≤ 2 × shortest → h ≤ 2·log₂(n+1) สูงกว่า AVL ได้แต่ยัง O(log n)
  • Insertion: ใส่เป็น red เสมอ (ไม่เปลี่ยน black-height) แล้วซ่อมเฉพาะเมื่อพังกฎ
  • Parent black → จบ
  • Parent red + uncle red → recolor (parent & uncle เป็น black, grandparent เป็น red) แล้วไต่ต่อที่ grandparent: เป็น "ปัญหาสี"
  • Parent red + uncle black/NIL → rotate + recolor ("ปัญหารูปทรง"): LL → right rotation ที่ grandparent, RR → left rotation, LR/RL → double rotation; node ที่ถูกเลื่อนขึ้นเป็น black, grandparent เป็น red
  • ถ้า root กลายเป็น red → recolor root เป็น black (เพิ่ม black ทุก path เท่ากัน จึงยัง balance)
  • Complexity: search/insert/delete ล้วน O(log n) งานซ่อมต่อระดับเป็น O(1); หมุนได้มากสุด 2 ครั้งต่อ operation
  • Java TreeMap/TreeSet ใช้ Red-Black; TreeSet: ค่าไม่ซ้ำ, เรียง ascending, ไม่ thread-safe, มี first()/last()
ตัวอย่าง: trace RB insert 10, 20, 30, 15, 25, 27, 5, 1, 7 (จุดสำคัญจากสไลด์)
  1. แทรก 10, 20 ปกติ; แทรก 30 → เกิด RR imbalance → rotate left ที่ 10
  2. แทรก 15 → parent/uncle เป็น red → recolor แล้วไต่ตรวจต่อ
  3. แทรก 27 → เคส LR: rotate left ที่ 25 แล้ว right ที่ 30, 27 ขึ้นเป็น black
  4. แทรก 1 → uncle red → recolor + propagate หยุดเพราะ parent เป็น black

Splay Tree

  • แนวคิด: ทุกครั้งที่ access → splay (ยก node นั้นขึ้นเป็น root) โดยยังคง BST invariant; ของที่ใช้บ่อยรวมอยู่บน ๆ, ของที่ไม่ค่อยใช้จมลงล่าง
  • ไม่ bookkeeping height เลย ยอมให้ unbalance ชั่วคราว; linear time เกิดได้แต่นาน ๆ ครั้ง
  • Amortized O(log n) ต่อ operation (M operations บน tree ขนาด N รวม O(M log N))
  • 6 เคส rotation: Zig/Zag (parent เป็น root, หมุนครั้งเดียว), Zig-zig/Zag-zag (หมุนที่ grandparent ก่อน แล้ว parent), Zig-zag/Zag-zig (หมุนที่ parent ก่อน แล้ว grandparent)
  • Delete: search + splay ตัวที่ลบขึ้น root → splay max ของ left subtree ขึ้น → ต่อ right ของเดิมเข้ากับ root ใหม่
  • เหมาะกับ workload ที่ access กระจุกอยู่กับข้อมูลก้อนเล็ก (locality)

Graph (L12)

นิยามสำคัญ

  • Graph G = (V, E): vertex ชุดจุด, edge ชุดเส้นเชื่อม (คู่ (v,w)); directed เรียก edge ว่า arc; undirected ถ้า (x,y) บังคับ (y,x) ด้วย
  • Loop (x,x), Multiedges, Simple graph = ไม่มี loop และ multiedge; Weighted = edge มีค่า (weight/cost/label)
  • Adjacent: w อยู่ติด v ถ้า (v,w) ∈ E; Degree = จำนวนเพื่อนบ้าน (directed แยก indegree/outdegree)
  • Sparse (|E| = O(|V|)) กับ Dense (|E| = O(|V|²))
  • Path: ลำดับ vertex ที่ติดกันทุกคู่; length = จำนวน edge (จากตัวเองถึงตัวเอง = 0); Simple path = vertex ไม่ซ้ำ; Cycle = path ที่ w1 = wn (≥ 2 vertex, ไม่ backtrack edge เดิม); DAG = directed ไม่มี cycle
  • Connected component: เซตใหญ่สุดที่ไปถึงกันได้ เป็น partition ของกราฟ undirected; Forest = กราฟที่ component เป็น tree
  • Bipartite: แบ่ง vertex เป็น V1, V2 โดย edge ข้ามฝั่งเท่านั้น (เช่น stable matching)
  • Subgraph H = (V′, E′) ของ G: V′ ⊆ V และ E′ ⊆ E (quick check: edge ต้องมี endpoint อยู่ใน V′ ด้วย)
  • Tree = connected, undirected, ไม่มี cycle; Spanning tree = subgraph ที่มี vertex ครบ + connected + ไม่มี cycle; MST = spanning tree ผลรวมน้ำหนักน้อยสุด (อาจไม่ unique; ถ้าน้ำหนักไม่ซ้ำกัน MST unique)
  • Graph ADT: getDegree(u), getAdjacent(u), isAdjacentTo(u,v)

Traversal: BFS และ DFS

  • สถานะ vertex: unvisited → discovered (frontier) → explored; queue/stack เก็บ discovered ที่ยังไม่ explored; ต้อง mark ตอน "เข้า queue/stack" ไม่ใช่ตอน pop
  • BFS = Queue (FIFO): สำรวจตัวที่ค้นพบก่อนก่อน ระดับแล้วระดับ; pseudocode ใช้ d[] (ระยะ) และ path[] (มาจากไหน); ในกราฟไร้น้ำหนัก BFS หา shortest path (น้อย edge สุด) ได้
  • DFS = Stack (LIFO): สำรวจตัวที่ค้นพบล่าสุดก่อน ลึกก่อน; มีทั้งแบบ recursive และ iterative (pre-order)
  • traverse ทุก edge อย่างน้อยที่สุด: เยี่ยมแต่ละ edge ≤ 2 ครั้ง
  • อื่น ๆ: Best-First Search (เลือก node ที่ "ดีที่สุด" ตาม heuristic), Restricted BFS

MST: Prim's Algorithm

  • ปลูก tree เดียวจาก vertex เริ่ม: ซ้ำ ๆ เลือก edge น้ำหนักน้อยสุดที่ ปลายใน tree 1 ข้าง + ปลายนอก 1 ข้าง จนครบทุก vertex
  • Pseudocode: key[v] = น้ำหนัก edge ถูกสุดที่เชื่อม v เข้า tree, parent[v] = เส้นที่เลือก; priority queue เลือก key น้อยสุด
  • adjacency list + PQ → O((V+E) log V); แบบ lazy คือ O(E log V)

Shortest Path: Dijkstra's Algorithm

  • Single-source shortest path เมื่อ น้ำหนักไม่ติดลบ; output dist[v], prev[v]
  • Lazy queue: library ไม่มี decreaseKey → push ซ้ำทุกครั้งที่ดีขึ้น แล้วเจอของเก่า (du > dist[u]) ข้าม ทำหน้าที่แทน visited; ค้น s→t สามารถ break เมื่อ u == t
  • Complexity: insert ได้มากสุด O(E) ครั้ง × heap O(log E) = O(E log V) (รวม init: O(V + E log V))
// Relax
alt = dist[u] + w(u,v)
if alt < dist[v]:
    dist[v] = alt
    prev[v] = u
    decreaseKey(v)
