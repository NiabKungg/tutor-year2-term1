กับดักที่พบบ่อย
  • fork() คืนค่า 0 ให้ process ลูก แต่คืน PID ของลูกให้ process แม่
  • signal() ในภาษา C ใช้ลงทะเบียน handler ไม่ใช่ฟังก์ชันส่ง signal
  • SIGKILL (เบอร์ 9) ปลายทาง catch หรือ ignore ไม่ได้ แต่ SIGTERM จัดการได้

Process และ Thread

1) เมื่อโปรแกรมเรียก pid = fork(); ในกรณีสร้างสำเร็จ ค่า pid ที่ process ลูกเห็นคืออะไร

เฉลย ก: fork() คืนค่า ใน child = 0, ใน parent = process ID ของ child (มากกว่า 0), ค่าติดลบ = สร้างไม่สำเร็จ โปรแกรมใช้ค่าที่ต่างกันนี้แยกว่าตัวเองเป็น parent หรือ child

2) ข้อใดถูกต้องเกี่ยวกับสิ่งที่ thread แต่ละตัวมีเป็น "ของตัวเอง" และสิ่งที่ "แชร์กัน" ภายใน process เดียวกัน

เฉลย ค: thread แต่ละตัวต้องมี program counter, register และ stack เป็นของตัวเอง (เก็บสถานะการทำงานและ local variable) แต่แชร์ code, data และ open files กับ process แม่ จึงถูกเรียกว่า lightweight process และ context switch ของ thread เร็วกว่า process

3) ใน Java ถ้า class Foo สืบทอด (extends) จาก class Bar อยู่แล้ว และต้องการให้ Foo ทำงานเป็น thread ด้วย ควรทำอย่างไร

เฉลย ข: Java ไม่รองรับ multiple inheritance จึง extends ทั้ง Bar และ Thread พร้อมกันไม่ได้ กรณีนี้ "บังคับ" ให้ใช้ implements Runnable แล้วห่อด้วย Thread object (new Thread(worker)) ก่อนเรียก start()

CPU Scheduling

4) "Convoy effect" ที่เกิดกับ FCFS scheduling หมายถึงอะไร

เฉลย ง: convoy effect คือ "short process behind long process" จากตัวอย่างสไลด์ถ้า P1 (24 หน่วย) มาก่อน P2, P3 (3 หน่วย) waiting เฉลี่ยเป็น 15 แต่ถ้าสลับให้ process สั้นมาก่อนเหลือเพียง 1 (วิธีคำนวณเต็มอยู่ข้อ 25)

5) ปัญหา starvation ใน Priority Scheduling แก้ได้ด้วยเทคนิคใด

เฉลย ข: starvation คือ process priority ต่ำอาจไม่ได้รันเลย Aging แก้โดยค่อย ๆ เพิ่ม priority ของ process เมื่อเวลาผ่านไป

IPC: Signal, Pipe และ Shared Memory

6) ฟังก์ชัน signal() ในภาษา C (#include <signal.h>) มีหน้าที่ใด

เฉลย ข: signal() ไม่ใช่ฟังก์ชันส่ง signal แต่ใช้ลงทะเบียน handler กับ OS (จุดที่นักศึกษาสับสนมากที่สุด) ถ้าจะส่ง signal ให้ตัวเองใช้ raise() และส่งให้ process อื่นใช้ kill()

7) ข้อใดถูกต้องเกี่ยวกับ SIGTERM และ SIGKILL

เฉลย ค: SIGTERM ยังเขียน handler จัดการหรือไม่สนใจได้ แต่ SIGKILL (เบอร์ 9) จัดการไม่ได้ "ถ้าได้รับ SIGKILL ต้องตาย" ตาม default ของ OS (signal เบอร์ 2 คือ SIGINT จาก Ctrl+C และคำสั่ง kill บน shell default คือ SIGTERM)

8) โปรแกรม client ที่มาใช้ shared memory ซึ่ง server สร้างเอาไว้แล้ว ข้อใดถูกต้อง

เฉลย ค: หัวใจของ shared memory คือ server กับ client ต้องใช้ key เดียวกันจึงชี้ไปก้อนเดียวกัน ฝั่ง client ใส่ size/flag = 0 ได้เพราะใช้ของที่สร้างไว้แล้ว และห้ามลบ (shmctl เป็นสิทธิ์ของ server เท่านั้น)

Synchronization และ Semaphore

9) สถานการณ์ใดเรียกว่า race condition

เฉลย ง: race condition คือกรณีหลาย process เข้าไปแก้ข้อมูลตัวเดียวกันพร้อมกัน ผลลัพธ์สุดท้ายขึ้นกับลำดับ (interleaving) เช่น ตัวอย่าง count++/count-- ของสไลด์ที่ count กลายเป็น 4 ทั้งที่ควรเป็น 5 (ตัวเลือก ค คือ deadlock ไม่ใช่ race condition)

10) ในโจทย์ Bounded-Buffer (N buffer) ค่าเริ่มต้นของ semaphore ทั้งสามตัวคือข้อใด

เฉลย ค: mutex กำหนด 1 (mutual exclusion), full กำหนด 0 (ยังไม่มี item), empty กำหนด N (buffer ว่างทั้งหมด)

11) กำหนดวิธีเข้าใช้ critical section ด้วย "คิวตายตัว แดง ไป เขียว ไป เหลือง" วันหนึ่งแดงไม่อยากเข้าใช้ ทั้งที่ section ว่าง เขียวกลับเข้าไม่ได้ตลอดไป วิธีนี้ละเมิดเงื่อนไขข้อใดของการแก้ปัญหา critical section

เฉลย ง: เงื่อนไข Progress ต้องการให้เลือก process ถัดไปจาก "process ที่อยากใช้เท่านั้น อย่าไปยุ่งกับ process ที่ไม่อยากใช้" คิวตายตัวทำให้เขียวเข้าไม่ได้ทั้งที่ section ว่างและแดงไม่ได้ต้องการใช้

12) Peterson's Solution ทำงานได้ภายใต้ข้อสมมติใด และใช้ตัวแปร shared อะไร

เฉลย ข: Peterson's Solution สำหรับ 2 process สมมติ LOAD/STORE เป็น atomic (interrupt ไม่ได้) และใช้ตัวแปร shared สองตัวคือ int turn (ตาใครเข้า) และ boolean flag[2] (พร้อมเข้าหรือยัง) ส่วน number[n]/choosing[n] เป็นตัวแปรของ Bakery Algorithm

Deadlock

13) แก้ปัญหา Dining Philosophers ด้วย semaphore chopstick[5] (binary ทุกตัวเริ่มต้น 1) ถ้านักปราชญ์ทั้ง 5 หิวพร้อมกัน และทุกคน wait(chopstick[i]) หยิบตะเกียบซ้ายสำเร็จพร้อมกัน จะเกิดอะไรขึ้นต่อไป

เฉลย ข: ตะเกียบ 5 ข้างถูกถือครบในมือทุกคน ทุกคน wait(chopstick[(i+1)%5]) ตะเกียบขวาแล้วเจอค่า 0 จึงติดรอทั้งหมด และจะวางตะเกียบซ้ายคืนได้ต้องกินเสร็จก่อน ซึ่งไม่มีวันเกิดขึ้น เป็น deadlock "ตายทั้งโต๊ะ" (เกิดจากโปรแกรมเมอร์จัดลำดับผิด ไม่ใช่ตัว semaphore)

14) Resource allocation graph ของระบบหนึ่งพบว่ามี cycle แต่ทรัพยากรบางประเภทที่เกี่ยวข้องกับ cycle มีหลาย instance จะสรุปได้อย่างไร

เฉลย ค: กฎของ resource allocation graph: ไม่มี cycle ไม่เกิด deadlock แน่นอน / มี cycle + ทรัพยากร 1 ประเภทมี 1 ชิ้น เกิดแน่นอน / มี cycle + มีหลายชิ้น สรุปได้แค่ "มีโอกาส" เท่านั้น (เช่น process นอก cycle อาจคืนทรัพยากรให้)

Memory Management

15) ระบบ Fixed-Partition Multiprogramming เกิด fragmentation ชนิดใด และ Variable-Partition เกิดชนิดใด

เฉลย ก: Fixed partition: partition ใหญ่กว่า job เหลือช่องว่างใน partition ของตัวเอง เป็น internal fragmentation ส่วน Variable partition: job ถูกถอดออกแล้วเหลือ holes เล็ก ๆ ที่ไม่พอให้ process ใหม่ เป็น external fragmentation (แก้ด้วย coalescing/compaction)

16) Address ที่ CPU ส่งออกมาเพื่ออ้างตำแหน่งในโปรแกรม (มองว่าโปรแกรมเริ่มที่ไบต์ 0) เรียกว่าอะไร และถูกแปลงเป็น address จริงใน RAM ด้วยฮาร์ดแวร์ใด

เฉลย ก: logical (virtual) address ออกจาก CPU ส่วน physical address คือตำแหน่งจริงใน RAM เพราะโปรแกรมถูกโหลดตามที่ OS จัดสรร (ไม่ใช่ไบต์ 0) ตัวแปลงคือ MMU (เช่น relocation register 14,000 + ไบต์ที่ 346 = 14,346)

17) ระบบมีช่องว่างหน่วยความจำขนาด 16, 14, 5 และ 30 MB มี process ใหม่ต้องการ 13 MB ถ้าใช้ Best Fit จะจัดสรรลงช่องใด และเหลือช่องว่างเท่าไร

เฉลย ง: Best Fit ไล่ดูทุกช่อง (16, 14, 5, 30) แล้วเลือกช่องที่พอดีที่สุดกับ 13 MB คือช่อง 14 MB เหลือเพียง 1 MB จัดสรรดีที่สุดแต่ช้าที่สุดเพราะต้องค้นครบทุกช่อง (เทียบ: First Fit ลง 16 MB เพราะเร็ว, Worst Fit ลง 30 MB เพื่อเหลือช่องใหญ่ไว้ใช้ต่อ)

Virtual Memory

18) หลักการของ demand paging คือข้อใด

เฉลย ข: demand paging นำ page เข้า memory เมื่อ needed เท่านั้น ทำให้ I/O น้อยลง, ใช้ memory น้อยลง, response เร็วขึ้น และรองรับ user มากขึ้น (เชื่อมกับ lazy swapper/pager)

19) ในระบบ demand paging เมื่อ process อ้างถึงเพจที่ "มีสิทธิ์ใช้ แต่ยังไม่ถูกโหลดเข้า memory" เหตุการณ์นี้เรียกว่าอะไร และ OS ดำเนินการอย่างไร

เฉลย ข: page fault = การอ้างเพจที่มีสิทธิ์ใช้แต่ยังไม่อยู่ใน memory (valid/invalid bit เป็น invalid) ขั้นตอน: interrupt, OS หา frame ว่าง, โหลดเพจจาก storage, อัปเดต page table (เก็บ frame + เปลี่ยน bit เป็น valid), ให้คำสั่งเดิมทำงานซ้ำ คราวนี้จะไม่ fault อีก

20) ปรากฏการณ์ Belady's anomaly (เพิ่มจำนวน frame แล้วจำนวน page fault กลับเพิ่มขึ้น) เป็นคุณสมบัติที่พบกับอัลกอริทึมใด

เฉลย ง: สไลด์มีหัวข้อ "FIFO Illustrating Belady's Anomaly" คือเพิ่มจำนวน frame แล้ว page fault กลับเพิ่มขึ้น (Optimal และ LRU ไม่มีปรากฏการณ์นี้) ตัวอย่างการคำนวณอยู่ข้อ 30

File System

21) ระบบไฟล์ใดที่ "ไม่มี journaling แต่เก็บไฟล์ใหญ่กว่า 4 GB ได้ และยัง compatible กับหลาย OS เหมาะกับ USB flash drive / SD card"

เฉลย ค: exFAT อยู่ตรงกลางระหว่าง FAT32 กับ NTFS: เก็บไฟล์ใหญ่กว่า 4 GB ได้ (FAT32 จำกัดไฟล์เดี่ยว 4 GB), volume ได้ถึง 128 PB แต่ไม่มี journaling (ต่างจาก NTFS/ext4/APFS ที่มีระบบช่วย recover) และ compatible กับหลาย OS เหมือน FAT จึงนิยมใช้กับ USB/SD card/external drive

22) สร้าง soft link (symbolic link) ด้วย ln -s ไปยังไฟล์ต้นทาง แล้วลบไฟล์ต้นทาง จะเกิดอะไรขึ้น

เฉลย ข: soft link เป็น "shortcut" ชี้ไปยังตัวไฟล์ (path) ไม่ใช่ inode ต้นทางลบเมื่อไรจึงกลายเป็น broken/dangling link ทันที ส่วน hard link ชี้ที่ inode และระบบใช้ reference counter (การลบ = ลด counter) จึงยังอ่านข้อมูลได้ครบตราบที่ counter ยังไม่เป็น 0 ข้อดี soft link คือข้าม file system ได้และทำกับโฟลเดอร์ได้

อัตนัย: Process และ CPU Scheduling

23) จงอธิบายความแตกต่างระหว่าง "program" กับ "process" พร้อมบอกว่า process มีข้อมูล (data) อะไรของตัวเองบ้าง และ process เรียกอีกอย่างว่าอะไรในระบบ time-sharing และ batch system

ดูเฉลย
  • Program = inactive entity เป็นแค่ไฟล์เก็บบนดิสก์
  • Process = program in execution เป็น active entity ที่ต้องการชุด resources
  • Process มีข้อมูลของตัวเอง: program counter, stack, data section (สถานะทั้งหมดถูกเก็บใน PCB)
  • ใน time-sharing system เรียก process ว่า Task ใน batch system เรียกว่า Job

(ข) SRTF: P1 รัน 0-2 พอ t = 2 แล้ว P2 มา (burst 4 น้อยกว่า remaining ของ P1 = 5) จึงขัดจังหวะ ที่ t = 4 P3 มา (1 น้อยกว่า 2) ขัดอีก ที่ t = 5 P4 มา เหลือ P1(5), P2(2), P4(4)

(ข) Turnaround (จบ - มา): P1 = 30, P2 = 5, P3 = 6 จากนั้น Waiting (turnaround - burst): P1 = 6, P2 = 2, P3 = 3 (เฉลี่ย ประมาณ 3.67 ms) RR ทำให้ response time ดีขึ้นแต่ turnaround แย่ลง

(ค) Quantum ใหญ่เกินไป จะเหมือนกลายเป็น FCFS / เล็กเกินไป จะ context switch ถี่เกิน เกิด overhead สูง และมีการรับประกันว่า process ท้ายสุดรอไม่เกิน (n-1) × q

อัตนัย: IPC และ Pipe

26) (ก) ระบุโมเดลของ IPC ทั้ง 3 แบบตามสไลด์ (ข) เมื่อ process ได้รับ signal process มีทางเลือกในการจัดการ signal ได้ 3 วิธี จงอธิบายแต่ละวิธีสั้น ๆ

ดูเฉลย

(ก) โมเดล IPC 3 แบบ: Signal, Shared memory, Message passing

(ข) 3 วิธีจัดการ signal:

  1. Catch เขียน routine (handler) ขึ้นมาเอง แล้วให้ OS เรียกเมื่อ signal มาถึง เช่น ผ่าน signal(SIGINT, handler)
  2. ใช้ default action ของ OS ปล่อย OS จัดการตามค่าเริ่มต้นของ signal นั้น (เช่น terminate, ignore, stop/continue)
  3. Mask สั่งให้ OS รีบัด (หน่วง) signal ประเภทนั้น ๆ ไว้ จนกว่า process จะถอด signal mask ออก

27) ให้โครงโปรแกรม pipe แม่-ลูก ดังนี้

pipe(pfd);              /* pfd[0] = ปลายอ่าน, pfd[1] = ปลายเขียน */
pid = fork();
if (pid == 0) {         /* ลูก = คนอ่าน */
    close(pfd[1]);
    while ((nread = read(pfd[0], buffread, 5)) != 0) printf("%s", buffread);
} else {                /* แม่ = คนเขียน */
    close(pfd[0]);
    sleep(2);
    write(pfd[1], buff, strlen(buff) + 1);
    close(pfd[1]);
    wait();
}

(ก) เพราะเหตุใดจึงต้องเรียก pipe() ก่อน fork() (ข) ระหว่าง 2 วินาทีที่แม่ sleep(2) อยู่ ลูกทำงานอยู่ในสถานะ/พฤติกรรมใด (เกี่ยวข้องกับคุณสมบัติของ read()) (ค) ถ้าแม่เปลี่ยนบรรทัด write เป็น write(pfd[1], buff, strlen(buff)); (ตัด +1 ออก) อาจเกิดปัญหาอะไรกับผลลัพธ์ที่ลูกพิมพ์ออกมา

ดูเฉลย

(ก) เพราะหลัง fork() ลูกได้รับ copy ทุกอย่างจากแม่รวมถึง file descriptor การสร้าง pipe ก่อน fork ทำให้ลูกได้ปลาย pipe ชุดเดียวกับแม่ ถ้าสร้างหลัง fork ลูกจะไม่รู้จัก pipe

(ข) read() เป็น blocking ลูกเรียก read ก่อนแต่ยังไม่มีข้อมูล จึง block รออยู่กับที่จนกว่าแม่จะเขียนข้อมูลเข้า pipe (แม่ sleep(2) ตั้งใจสาธิต blocking พอดี)

(ค) strlen(buff) ไม่นับ '\0' จึงไม่ได้ส่งตัวปิดท้ายไปด้วย โปรแกรมทำงานเหมือนปกติแต่ตัวสุดท้ายจะมีตัวอักษรขยะ (เศษข้อมูลเก่าค้างใน buffer) โผล่มา ฟังก์ชัน string ของ C อาศัย '\0' จึงต้องเขียน strlen(buff) + 1

(ก) Need = Max - Allocation:

  • P1: Need (1, 2, 2) ไม่เกิน (3, 3, 2) รันจบ, Work = (3, 3, 2) + Allocation P1 (2, 0, 0) = (5, 3, 2)
  • P3: Need (0, 1, 1) ไม่เกิน (5, 3, 2) รันจบ, Work = (5, 3, 2) + (2, 1, 1) = (7, 4, 3)

  • P0: Need (7, 4, 3) ไม่เกิน (10, 4, 7) รันจบ, Finish ครบทุกตัว จึงระบบอยู่ใน safe state

อัตนัย: Memory และ Virtual Memory

29) ระบบ paging หนึ่งมี logical address ขนาด m = 5 บิต และ page size = 4 ไบต์ โดย page table ระบุว่า page 0 ไป frame 5, page 1 ไป frame 4, page 2 ไป frame 1, page 3 ไป frame 7

(ก) address space มีขนาดเท่าใด แบ่งบิตเป็น page number กี่บิต กับ offset กี่บิต และมีเพจได้ทั้งหมดกี่เพจ (ข) หา physical address ของอักษร C ที่อยู่ (page 0, offset 2) และอักษร K ที่อยู่ (page 2, offset 2) ใช้สูตร physical = frame × page size + offset (ค) เพราะเหตุใดการอ่านข้อมูล 1 ครั้งจึงต้องเข้าถึง memory 2 ครั้งเมื่อมี page table ใน RAM และถ้า memory access = 1 µs, TLB access = 0.1 µs, hit ratio = 0.8 จงหาค่า Effective Access Time (EAT)

ดูเฉลย

(ก) Address space = 2^5 = 32 ไบต์ offset ใช้ n = 2 บิต (เพราะ 2^2 = 4 = page size) page number = 5 - 2 = 3 บิต จึงมีได้ 2^3 = 8 เพจ (8 × 4 = 32 ไบต์พอดี)

(ข) C: page 0 ไป frame 5 ได้ physical = 5 × 4 + 2 = ไบต์ที่ 22 / K: page 2 ไป frame 1 ได้ physical = 1 × 4 + 2 = ไบต์ที่ 6

(ค) เพราะ Page Table อยู่ใน RAM ครั้งแรกต้องอ่าน Page Table เพื่อรู้ว่าเพจอยู่ frame ไหน ครั้งที่สองจึงไปยัง address จริง คำนวณ EAT แบบถ่วงน้ำหนัก: EAT = 0.8 × (0.1 + 1) + 0.2 × (0.1 + 2) = 0.88 + 0.42 = 1.3 µs (ลดจาก 2 µs เมื่อไม่มี TLB เพราะ TLB hit ช่วยให้ไม่ต้องเข้าถึง page table)
