1. Virtualization Technology

Virtualization คือเทคโนโลยีที่อนุญาตให้ "สร้างเวอร์ชันเสมือน (virtual version) ของทรัพยากร" เช่น เครื่อง server โดยเราสร้าง Virtual Machine (VM) ซึ่งเป็นสภาพแวดล้อมที่สมบูรณ์ในตัวเอง (self-contained)

นิยมใช้ VM เพื่อทดลองใช้ซอฟต์แวร์ใหม่ ๆ โดยไม่เสี่ยงทำความเสียหายกับ host operating system

Hypervisor (Virtual Machine Monitor)

Hypervisor คือซอฟต์แวร์ที่ทำหน้าที่สร้างและจัดการ VM บนเครื่อง host แบ่งเป็น 2 ประเภท

ประเภท Hypervisorลักษณะตัวอย่าง
Bare-metal Hypervisorทำงานบนฮาร์ดแวร์ของเครื่องโดยตรงVMware ESXi, Microsoft Hyper-V
Hosted Hypervisorทำงานบน operating system ที่มีอยู่แล้ว (บน OS อื่น)VMware Workstation, Oracle VirtualBox
ประเด็นสำคัญ
  • WSL (Windows Subsystem for Linux) คือ virtual machine แบบ light-weight ที่ integrate กับ host อย่างแนบแน่น (tightly integrated) ดูรายละเอียดในหัวข้อ WSL
  • Oracle VirtualBox คือ cross-platform virtualization application ติดตั้งได้บนเครื่อง Intel/AMD ที่รัน Windows, Mac, Linux หรือ Solaris และรัน "guest" OS (VM) ในหน้าต่างของ host OS ได้
ตัวอย่าง: ขั้นตอนติดตั้ง Ubuntu บน Oracle VirtualBox (สรุป)
  1. Downloads : ดาวน์โหลด VirtualBox จากเว็บทางการให้ตรงกับ OS ของ host (เช่น "x86/amd64" for Windows hosts) แล้วติดตั้งแบบค่า default
  2. Create Virtual Machine : กดปุ่ม New ตั้งชื่อ VM (เช่น ubuntu1404) โปรแกรมจะเลือก Type = Linux, Version = Ubuntu (64 bit) ให้เอง จากนั้นตั้ง memory size (ตัวอย่าง: RAM 12GB จัดสรร 8192 MB) และยอมรับ "Create a virtual hard drive now"
  3. เปลี่ยน storage type จาก Dynamically allocated เป็น Fixed size เพื่อเพิ่ม performance แล้วเลือกขนาด disk (ตัวอย่าง 100 GB)
  4. ตั้งค่าก่อนติดตั้ง : Settings → Storage → เลือก Empty ใต้ Controller:IDE → กดไอคอน CD/DVD เพื่อ mount ไฟล์ Ubuntu ISO (ต้องเป็น 64-bit) และต้องเปิด VT-x / Virtualization Technology ใน BIOS ด้วย ที่ System สามารถเพิ่มจำนวน processors ได้ (default = 1, ตัวอย่างเปลี่ยนเป็น 4)
  5. Install Ubuntu : กด Start → "Install Ubuntu" → เลือก "Erase disk and install Ubuntu" → Install Now → กรอก name/username/password (user นี้จะมีสิทธิ์ root/sudo) → รอจนเสร็จ → Restart Now → login ด้วย password ที่ตั้งไว้
  6. Guest Additions : หลังติดตั้งถ้าหน้าจอเล็กเกินไป ให้ติดตั้ง Guest Additions ผ่านเมนู Devices > Insert Guest Additions CD images → กด Run → ใส่รหัสผ่าน → รีสตาร์ต (ต้องมีสิทธิ์ sudo/root ถ้าไม่มีใช้ sudo adduser USERNAME sudo)
อ่านเพิ่ม: ความสามารถของ Guest Additions และการ Share Folders

Guest Additions ให้ความสามารถเพิ่ม 4 อย่าง: mouse pointer integration, better video support, shared folders, shared clipboard

การ Share Folders (ต้องติดตั้ง Guest Additions ก่อน):

  1. ไปที่ Devices > Shared folders settings → เลือก Machine Folders → กดปุ่ม add (+) → เลือกโฟลเดอร์ → ติ๊ก Auto-mount และ Make Permanent
  2. เพิ่ม user เข้ากลุ่ม vboxsf (จำเป็นสำหรับใช้ Shared Folder): sudo adduser brb vboxsf (แทน brb ด้วยชื่อ account ใน Ubuntu) แล้วรีสตาร์ต
  3. โฟลเดอร์จะปรากฏใน /media/ ขึ้นต้นด้วย sf_ (เช่น sf_Downloads)
ข้อผิดพลาดที่พบบ่อย
  • VirtualBox จะสร้าง swap partition ขนาดเท่ากับ base memory ที่ใส่ จึงต้องเผื่อขนาด virtual hard drive ให้ใหญ่พอ (แบ่งเป็น root / และ swap)
  • ลืมเปิด VT-x / Virtualization Technology ใน BIOS แล้ว VM จะเริ่ม Ubuntu 64-bit ไม่ได้
  • การใช้ shared folder โดยตรงกับข้อมูลขนาดใหญ่จะ ลด performance เมื่อเทียบกับ native (Ubuntu) system
  • ใช้ shared folder ไม่ได้เพราะลืมเพิ่ม user เข้ากลุ่ม vboxsf ก่อน
มักออกสอบ
  • จำแนกประเภท hypervisor: bare-metal = VMware ESXi, Microsoft Hyper-V / hosted = Oracle VirtualBox, VMware Workstation
  • นิยาม virtualization: การสร้าง virtual version ของทรัพยากร เช่น server บนฮาร์ดแวร์เดียว (ไม่ใช่ dual-boot)
  • WSL ถูกจัดเป็น light-weight VM ที่ tightly integrated กับ host
  • user ที่สร้างระหว่างติดตั้ง Ubuntu จะมีสิทธิ์ root/sudo และความสามารถ 4 อย่างของ Guest Additions

2. WSL (Windows Subsystem for Linux)

WSL ให้ developer รันสภาพแวดล้อม GNU/Linux บน Windows ได้โดยตรง (unmodified) โดยไม่ต้องใช้ traditional virtual machine หรือ dual-boot ติดตั้ง Linux distributions ได้หลายตัว เช่น Ubuntu, Debian, Kali, OpenSUSE, Arch Linux

สิ่งที่ทำได้: รัน command-line tools เช่น grep, sed, awk, รัน Bash scripts, รัน vim, emacs, tmux, ภาษา NodeJS/Python/C/C++/Rust/Go, services อย่าง SSHD, MySQL, Apache, MongoDB, PostgreSQL และติดตั้งซอฟต์แวร์เพิ่มด้วย package manager ของ distro นั้น

การติดตั้ง WSL (วิธีปกติ : คำสั่งเดียว)

เปิด PowerShell หรือ Command Prompt แบบ Run as administrator แล้วสั่ง:

wsl --install

คำสั่งนี้ทำงาน 5 อย่างให้อัตโนมัติ:

  1. เปิด optional components: Windows Subsystem for Linux และ Virtual Machine Platform
  2. ดาวน์โหลดและติดตั้ง Linux kernel ล่าสุด
  3. ตั้ง WSL 2 เป็น default
  4. ดาวน์โหลดและติดตั้ง Ubuntu (default distribution) เปลี่ยนได้ด้วย -d เช่น wsl --install -d <Distribution Name>
  5. restart เครื่อง

เงื่อนไข: Windows 10 version 2004+ (Build 19041+) หรือ Windows 11 / สำหรับ WSL 2 ต้องเป็น Windows 11 หรือ Windows 10 Version 1903 Build 18362 ขึ้นไป (เช็คด้วย winver) / WSL รุ่นแจกผ่าน Microsoft Store จะได้รับ update เร็วกว่ารอ OS update (wsl.exe --update)

อ่านเพิ่ม: ติดตั้งแบบ manual (Windows เวอร์ชันเก่า)
  1. เปิด "Windows Subsystem for Linux": dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
  2. เช็คเงื่อนไข WSL 2 (Build 18362+ สำหรับ x64)
  3. เปิด Virtual Machine Platform: dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart แล้ว restart
  4. ดาวน์โหลดและรัน WSL2 Linux kernel update package
  5. ตั้ง WSL 2 เป็น default: wsl --set-default-version 2
  6. ติดตั้ง Linux distribution จาก Microsoft Store (Ubuntu 18.04/20.04/22.04 LTS, Debian, Kali, openSUSE ฯลฯ) → กด "Get" → เปิดครั้งแรกจะให้สร้าง user account และ password

เปรียบเทียบ WSL 1 กับ WSL 2

WSL 2 (ค่า default ของการติดตั้งใหม่) ใช้เทคโนโลยี virtualization รัน Linux kernel จริง ภายใน lightweight utility VM ที่ระบบจัดการให้ (managed VM) โดย Linux distributions ทำงานเป็น isolated containers ภายใน VM นั้น

ประเด็นWSL 1WSL 2
สถาปัตยกรรมใช้ translation layer ที่ทีม WSL สร้างขึ้นใช้ Linux kernel จริงใน managed VM
System callไม่รองรับเต็มFull system call compatibility
File IOช้ากว่าเร็วกว่ามาก (unpack tarball เร็วขึ้นถึง 20x, git clone/npm install/cmake เร็วขึ้น 2-5x)
เข้าถึงไฟล์ฝั่ง Windowsเร็วกว่าช้ากว่าข้าม OS file system
VMware/VirtualBoxทำงานร่วมได้WSL 2 ทำงานกับ VMware 15.5.5+ ได้ แต่ VirtualBox 6+ แม้ระบุว่ารองรับก็ยังมีปัญหา (unsupported)
systemd / IPv6ไม่รองรับรองรับ

กรณีที่ควรใช้ WSL 1

  • ต้องเก็บ project files ใน Windows file system
  • ต้อง cross-compile ด้วยเครื่องมือ Windows + Linux บนไฟล์เดียวกัน
  • ต้องใช้ serial port หรือมีข้อจำกัดด้าน memory แบบเข้มงวด (cache ของ WSL 2 จะคืน memory ก็ต่อเมื่อ shutdown)
  • ต้องการ IP ร่วม network เดียวกับ host (WSL 2 ใช้ NAT ทำให้ IP เปลี่ยนเมื่อ restart)

คำสั่ง wsl ที่ต้องรู้ (รันใน PowerShell/CMD : ใน Bash ให้ใช้ wsl.exe)

หลังติดตั้ง (Best practices)

  • ครั้งแรกจะให้ตั้ง Linux username/password (แยกจาก Windows account) user นี้เป็น Linux administrator ใช้ sudo ได้ และเป็น default user ที่ sign-in อัตโนมัติ
  • เปลี่ยน/รีเซ็ตรหัสผ่านด้วย passwd : ถ้าลืมรหัสใช้ wsl -u root (หรือ wsl -d Debian -u root) แล้ว passwd <username>
  • อัปเดตแพ็กเกจ (Windows จะไม่อัปเดต Linux ให้อัตโนมัติ): sudo apt update && sudo apt upgrade
  • แนะนำติดตั้ง Windows Terminal (เปิดหลาย tab/pane, สลับหลาย distro ได้)
  • การเก็บไฟล์เพื่อ performance ที่ดี: เก็บ project file ไว้ใน file system เดียวกับเครื่องมือที่ใช้ ถ้าทำงานด้วยเครื่องมือ Linux ให้เก็บใน Linux FS: \\wsl$\<DistroName>\home\<UserName>\Project
  • เปิด Windows File Explorer ที่ directory ปัจจุบัน: explorer.exe . : เปิด project ใน VS Code: code .
อ่านเพิ่ม: Interoperability ผสมคำสั่ง Windows กับ Linux
  • รัน Linux tools จาก Windows: wsl ls -la (ทำงานใน working directory เดียวกัน, เป็น default user, sudo/piping/redirect ใช้ได้) เช่น wsl sudo apt-get update
  • ผสมคำสั่ง: wsl ls -la | findstr "git" หรือ dir | wsl grep git หรือ ipconfig.exe | grep IPv4 | cut -d: -f2
  • รัน Windows tools จาก Linux: พิมพ์ชื่อ + .exe เช่น notepad.exe .bashrc, ping.exe www.microsoft.com, cmd.exe /C dir
  • เทียบผลลัพธ์: ใน PowerShell get-date = วันที่ฝั่ง Windows, wsl date = วันที่ฝั่ง Linux
  • WSLENV ใช้แชร์ environment variables ระหว่าง Windows กับ WSL (มี flag /p, /l, /u, /w)
อ่านเพิ่ม: Bash พื้นฐาน, pipe และ redirect บน Ubuntu
pwd                      # ดู path ของ directory ปัจจุบัน
mkdir hello_world        # สร้าง directory ใหม่
cd hello_world           # เปลี่ยน directory
ls                       # ดูเนื้อหาใน directory
ls -l                    # แสดงรายละเอียด (เวลาแก้ไขล่าสุด, permission)
touch hello_world.txt    # สร้างไฟล์ใหม่
cat hello_world.txt      # ดูเนื้อหาไฟล์
code hello_world.txt     # เปิดแก้ไขด้วย VS Code
notepad.exe hello_world.txt

ติดตั้งโปรแกรม: sudo apt-get install <app_name> (Arch: sudo pacman -S, openSUSE: sudo zypper install, Alpine: sudo apk add, RHEL: sudo yum install)

Pipe | ส่ง output ของคำสั่งหน้าไปเป็น input ของคำสั่งหลัง:

cat fruits.txt | sort           # เรียงลำดับ
cat fruits.txt | grep P         # ค้นหาบรรทัดที่มี "P"

Redirect > ส่ง output ไปยังไฟล์:

cat fruits.txt | sort > sorted_fruit.txt
ข้อผิดพลาดที่พบบ่อย
  • ถ้า wsl --install แล้วเห็น help text แปลว่า WSL มีอยู่แล้ว : ให้ใช้ wsl --list --online ดู distro แล้ว wsl --install -d <DistroName>
  • wsl --unregister ลบ distro พร้อมข้อมูล หายถาวร ใช้ระวัง
  • ตอนตั้งรหัสผ่าน Linux ครั้งแรกจอจะไม่แสดงอะไรเลยขณะพิมพ์ เรียกว่า blind typing ไม่ใช่คีย์บอร์ดเสีย
  • เห็น /mnt/ ใน path (เช่น /mnt/c/Users/...) แปลว่ากำลังทำงานบน mounted drive ฝั่ง Windows ซึ่ง ช้ากว่า การเก็บไฟล์ใน Linux FS
  • WSL 2 มีปัญหากับ VirtualBox 6+ แม้ระบุว่ารองรับ (ยังถือว่า unsupported) ส่วน VMware ต้องเป็นเวอร์ชัน 15.5.5 ขึ้นไป
มักออกสอบ
  • wsl --install ทำ 5 อย่าง: เปิด feature (WSL + Virtual Machine Platform), ติดตั้ง kernel ล่าสุด, ตั้ง WSL 2 default, ติดตั้ง Ubuntu, ต้อง restart
  • เทียบ WSL 1/WSL 2: WSL 1 ใช้ translation layer, WSL 2 ใช้ Linux kernel จริงใน managed VM ได้ full system call และ file IO เร็วกว่า (20x / 2-5x)
  • การเข้าถึงไฟล์ฝั่ง Windows WSL 1 เร็วกว่า (จุดนี้ออกสลับกันบ่อย)
  • wsl -l -v = ดู distro + สถานะ + เวอร์ชัน, wsl --set-version <distro> 2 = เปลี่ยนเวอร์ชัน, wsl --shutdown = หยุดทั้งหมด
  • เงื่อนไขเวอร์ชัน: Windows 10 version 2004+ (Build 19041+) หรือ Windows 11 เช็คด้วย winver

Linux File Permissions และ chmod

File permissions เป็นหัวใจของ การควบคุมการเข้าถึงและความปลอดภัย กำหนดว่าใคร read/write/execute ได้ ประกอบด้วย 3 ชุด:

  • User (Owner) : สิ่งที่เจ้าของไฟล์ทำได้
  • Group : สำหรับสมาชิกกลุ่มของไฟล์
  • Other : ผู้ใช้อื่นทั้งหมดบนระบบ

โครงสร้าง -rwxrwxrwx : ตัวแรกคือ file type (- คือ regular file, d คือ directory) จากนั้น 3 ตัวคือ rwx ของ owner, 3 ตัวถัดไปของ group, 3 ตัวสุดท้ายของ other

แปลง binary เป็น octal: บวกค่าของ r (read) = 4, w (write) = 2, x (execute) = 1 ในแต่ละชุด

ตัวอย่าง: ถอดรหัส permission เป็นเลข octal
  1. rwxr-xr-- : owner rwx = 4+2+1 = 7, group r-x = 4+0+1 = 5, other r-- = 4+0+0 = 4 รวมได้ 744
  2. rwxr-xr-x : (4+2+1)(4+0+1)(4+0+1) = 755 (ตัวอย่างตรงจากสไลด์: 755 = rwx สำหรับ owner, rx สำหรับ group และ world)
  3. rwxrwxrwx = 777 = read, write, execute สำหรับทุกคน

แก้ permission ด้วย chmod:

chmod 755 myfile      # ตั้ง permission เป็น 755
chmod +x myfile       # เพิ่ม execute permission ให้ทุก user

4. VI/VIM Editor

vi (visual editor) คือ default editor ที่มากับ UNIX operating system มี 3 mode หลัก:

  • Command mode : คำสั่งที่กระทำต่อไฟล์ (vi เริ่มต้นที่ mode นี้)
  • Insert mode : ข้อความที่พิมพ์จะถูกใส่ลงไฟล์
  • Visual mode : ใช้ mark/select ข้อความในไฟล์

การสลับ mode: เข้า Insert mode กด i : เข้า Visual mode กด v หรือ Ctrl+V (visual block) : เข้า Command(line) mode พิมพ์ : : กลับ Normal mode กด esc

รูปแบบคำสั่ง: vi filename และ [count][command] (count ทำให้คำสั่งทำงานซ้ำ เช่น 5dd)

ข้อผิดพลาดที่พบบ่อย
  • ออกจาก input mode ได้ด้วยปุ่ม Esc เท่านั้น (กด RETURN ไม่ได้ผล)
  • :q ถ้ายังไม่ได้ save จะไม่ยอมออก ต้องใช้ :q! เพื่อออกโดยไม่บันทึก
  • สับสน p (วางหลัง cursor) กับ P (วางหน้า cursor) และ u (undo ครั้งล่าสุด) กับ U (undo ทั้งบรรทัด)

Visual mode และ Command-line mode

  • กด v → Visual mode (mark ตามบรรทัด, สถานะแสดง -- VISUAL LINE --)
  • กด Ctrl+V → Visual Block mode (mark เป็นบล็อก, สถานะแสดง -- VISUAL BLOCK --)
  • Command-line mode ใช้รันคำสั่งขั้นสูง: :w บันทึก buffer ลงไฟล์, :q ปิดโปรแกรม, :%s/old/new/g ค้นหาและแทนที่ old ด้วย new ทุกจุดในเอกสาร

รูปแบบ search & replace: :[address]s/old_text/new_text/ โดย address ได้แก่ . = บรรทัดปัจจุบัน, n = บรรทัดที่ n, .+m = บรรทัดปัจจุบันบวก m, $ = บรรทัดสุดท้าย, /string/ = บรรทัดที่มี string, % = ทั้งไฟล์, [addr1],[addr2] = ช่วง

ตัวอย่าง: search and replace ใน vi
  1. :.,.+10s/Banana/Kumquat : แทนที่จุดแรกใน 11 บรรทัดนับจากบรรทัดปัจจุบัน
  2. :%s/apple/pear/g : แทนที่ apple ด้วย pear ทุกจุดในไฟล์
  3. :%s/.$// : ลบตัวอักษรสุดท้ายของทุกบรรทัด (เช่น ตัด ^M จากการ transfer ไฟล์)
อ่านเพิ่ม: Regular expressions, คำสั่งจัดการไฟล์, parameters และการ scroll
  • Regular expressions: ^ ต้นบรรทัด, $ ท้ายบรรทัด, . ตัวอักษรใด ๆ, * ตัวอักษรก่อนหน้าซ้ำ, .* ทุกอย่าง
  • คำสั่งจัดการไฟล์: :w name (save เป็นชื่อใหม่), :sh (ไปรัน shell command, กลับด้วย Ctrl+D)
  • Parameters: :set number / :set nonumber (แสดงเลขบรรทัด), :set autoindent, :set showmatch, :set showmode, :set list, :set all
  • ย้ายข้อความข้ามไฟล์: vi old → "a10yy (yank 10 บรรทัดเข้า buffer a) → :w → :e new → "ap
  • Scroll หน้าจอ: Ctrl+D/Ctrl+U (ครึ่งจอลง/ขึ้น), Ctrl+F/Ctrl+B (เลื่อนหน้า), z<CR>/z./z- (จัดบรรทัดปัจจุบันไปบน/กลาง/ล่างของจอ), Ctrl+G (แสดงเลขบรรทัดปัจจุบันและข้อมูลไฟล์)

  • บันทึกแล้วออก: :wq, :x, ZZ : ออกไม่บันทึก: :q!

5. Docker พื้นฐาน

Docker คือ platform ที่ช่วย developer package application พร้อม dependencies, libraries และ configurations ทั้งหมดไว้ในหน่วยเดียวเรียกว่า "container" ทำให้ app portable และรันได้ consistent ในทุกสภาพแวดล้อม การรัน Docker ได้ 2 ทาง: Docker Desktop หรือ Docker CLI

Image vs Container

  • Docker Image = read-only template ที่มีคำสั่งสำหรับสร้าง container : image เป็น immutable (แก้ไม่ได้ ถ้าต้องแก้ต้อง build image ใหม่)
  • Docker Container (Instance) = runnable instance ของ image : จาก image เดียวสร้าง container ได้หลายตัว : container คือ isolated environment ที่ app ทำงานอยู่
  • Docker Hub (hub.docker.com) = container registry ที่ใหญ่ที่สุดในโลก ใช้เก็บ/จัดการ/แชร์ image และมี official images สำเร็จรูปมากมาย

Virtualization vs Containerization

ประเด็นVirtualizationContainerization
IsolationVM และ OS ถูก isolate เต็มรูปแบบisolate containers กับ host OS และระหว่างกัน (แต่ถ้า attacker คุม host ได้ container ทั้งหมดมีความเสี่ยง)
Different OShost ได้หลาย OS สมบูรณ์ แต่ละอันมี kernel ของตัวเองทุก container รันผ่าน user mode บน OS เดียว
Guest supportใช้ OS ได้หลากหลายบนเครื่องเดียวขึ้นกับ host OS : Linux container รันบน Windows ไม่ได้ (และกลับกัน)
Deploymentแต่ละ VM มี hypervisor ของตัวเองใช้ Docker deploy container เดี่ยว หรือ Kubernetes orchestrate หลาย container หลายเครื่อง

Dockerfile

Docker build image โดยการอ่าน instruction จาก Dockerfile ("It all starts with a Dockerfile")

Instructionหน้าที่
FROM <image>กำหนด base image
RUN <command>รันคำสั่งใน layer ใหม่บน image ปัจจุบันแล้ว commit ผลลัพธ์
WORKDIR <directory>ตั้ง working directory ให้ RUN/CMD/ENTRYPOINT/COPY/ADD ที่ตามมา
COPY <src> <dest>copy ไฟล์/โฟลเดอร์จาก src ใส่ filesystem ของ container ที่ path dest
CMD <command>กำหนด default program เมื่อสตาร์ต container (1 Dockerfile มีได้ 1 CMD : ถ้ามีหลายอันจะใช้เฉพาะอันสุดท้าย)

Instruction เพิ่มเติมที่พบในสไลด์: MAINTAINER (ผู้ดูแล), ENV (ตั้ง environment variable), ADD (คล้าย COPY เช่น ADD database.sql /docker-entrypoint-initdb.d), EXPOSE (ประกาศ port)

ตัวอย่าง: Dockerfile ของ Node.js (พร้อม .dockerignore ที่มี node_modules, npm-debug.log)
  1. เขียน Dockerfile: 
    FROM node:18-alpine
WORKDIR /nodejs_test
COPY package.json .
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "app.js"]
  2. build แล้วรัน: 
    $ docker build -t nodejs-app .
$ docker run -d -p 8080:3000 nodejs-app
  3. สังเกต -p = จับคู่ port: 8080:3000 แปลว่า port 8080 ของ host → port 3000 ของ container, -d = รันแบบ detached (background)
อ่านเพิ่ม: ตัวอย่าง Dockerfile Python Flask และ mysql + phpMyAdmin

Python Flask บน Ubuntu:

# syntax=docker/dockerfile:1
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y python3 python3-pip
RUN pip install flask==3.0.*
COPY hello.py /
ENV FLASK_APP=hello
EXPOSE 8000

$ docker build -t py-test:latest .
$ docker run -p 127.0.0.1:8000:8000 py-test:latest

mysql (มี database.sql สำหรับสร้าง database/table อัตโนมัติ):

FROM mysql:8.0.32
WORKDIR /app
MAINTAINER anupong.ba@kmitl.ac.th
ENV MYSQL_ROOT_PASSWORD=123456
ENV MYSQL_USER=anupong
ENV MYSQL_PASSWORD=123456

$ docker build -t mysqldb-test:latest .
$ docker run --name mysql-server --restart unless-stopped \
  -d -p 3306:3306 mysqldb-test \
  --default-authentication-plugin=mysql_native_password
$ docker run --name phpmyadmin -d \
  --restart unless-stopped -p 8088:80 \
  --link mysql-server:db phpmyadmin

ตัวเลือกสำคัญ: --name ตั้งชื่อ container, --restart unless-stopped รีสตาร์ตอัตโนมัติ, -d background, -p host:container map port, --link mysql-server:db เชื่อม container (ตั้งชื่อ alias ว่า db)

$ docker tag py-test abanjong/py-test:latest
$ docker push abanjong/py-test:latest

Docker Compose

Docker Compose คือเครื่องมือสำหรับ define และรัน multi-container Docker applications : orchestrate หลาย container เป็น application เดียวที่ coherent ใช้ไฟล์ YAML (docker-compose.yml) กำหนด services, networks, volumes ของ application

อ่านเพิ่ม: โครงสร้าง docker-compose.yml (mysql + phpMyAdmin)
version: '3.7'
services:
  db:
    image: mysql:latest
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: your_root_password
      MYSQL_DATABASE: your_database_name
      MYSQL_USER: your_username
      MYSQL_PASSWORD: your_password
    volumes:
      - ./mysql_data:/var/lib/mysql
    ports:
      - "3306:3306"
  phpmyadmin:
    image: phpmyadmin/phpmyadmin:latest
    restart: always
    depends_on:
      - db
    environment:
      PMA_HOST: db
      MYSQL_ROOT_PASSWORD: your_root_password
    ports:
      - "8080:80"
  • service db: image mysql, restart policy (รีสตาร์ตอัตโนมัติ), environment variables (root password, database name, username, password), volumes (mount ./mysql_data เพื่อ persist ข้อมูล), ports (3306:3306)
  • service phpmyadmin: restart policy, depends_on (ให้เริ่มหลัง mysql), environment (PMA_HOST, root password), ports (host 8080 → container 80)
$ docker compose up -d      # เริ่ม containers
$ docker compose down       # หยุดและลบ containers
ข้อผิดพลาดที่พบบ่อย
  • ไปแก้ค่าใน image ที่ build แล้วไม่ได้ เพราะ image เป็น immutable ต้องแก้ Dockerfile แล้ว build ใหม่
  • เขียน CMD หลายบรรทัดใน Dockerfile แล้วคิดว่าทำงานทุกอัน: จริง ๆ ใช้เฉพาะ CMD ตัวสุดท้าย
  • พยายามรัน Linux container บน Windows host โดยตรงไม่ได้ เพราะ container ทุกตัวรันผ่าน user mode บน OS เดียว (ผูกกับ host OS)
  • สลับลำดับใน -p: รูปแบบคือ -p host:container เช่น -p 8080:3000 = host 8080 → container 3000 ไม่ใช่กลับกัน
มักออกสอบ
  • นิยาม: image = read-only template (immutable), container = runnable instance ของ image สร้างหลายตัวจาก image เดียวได้
  • Dockerfile instructions หลัก: FROM, RUN, WORKDIR, COPY, CMD (ใช้เฉพาะอันสุดท้าย) และเสริม MAINTAINER, ENV, ADD, EXPOSE
  • docker build -t nodejs-app . = build จาก Dockerfile ใน directory ปัจจุบัน / docker run -d -p 8080:3000 nodejs-app = รัน background map port
  • docker ps = container ที่รันอยู่, docker images/docker rmi = ดู/ลบ image, docker tag + docker push = backup ขึ้น Docker Hub
  • Docker Compose ใช้ YAML จัดหลาย container: docker compose up -d เริ่ม / docker compose down หยุดและลบ

6. exec() Family : การแทนที่ process image ใน Unix

ทำไมต้องมี exec

ระบบ Unix-like แยกเรื่อง "สร้าง process" ออกจาก "รัน program อื่น" โดยมี design idea ว่า:

  • fork() สร้าง process ใหม่ (child = สำเนาของ shell)
  • exec() แทนที่ program ที่ทำงานอยู่ข้างใน process
  • ทั้งคู่รวมกันทำให้ shell เริ่มคำสั่งต่าง ๆ ได้ในขณะที่ยังคุมระบบไว้ได้
Shell process → fork() → Child copy of shell → exec() → New program (ls, gcc, python)

สิ่งที่ exec ทำ (execve)

Process PID 4210 ที่รัน program A (code + data) เมื่อเรียก execve() → ยังเป็น same PID 4210 แต่กลายเป็น program B (new code + data)

หัวใจสำคัญ: "The process is not cloned. Its running program is replaced." : process ไม่ได้ถูกโคลนเพิ่ม แต่ program ที่กำลังรันถูกแทนที่ (PID เดิมยังอยู่)

Heap-reinitialized
Data / BSS-new values

สรุป: after exec คือ same process, new program B

สมาชิกตระกูล exec และความหมายของตัวอักษร

ตัวอักษรในชื่อบอกวิธีส่ง arguments, การค้นหา program, และ environment:

  • l = list arguments (ส่ง argument เป็น list)
  • v = vector / argv[] (ส่ง argument เป็น array)
  • p = search PATH (ค้นหา program จาก PATH : ถ้าไม่มี p ต้องระบุ exact path)
  • e = custom envp[] (ส่ง environment ของตัวเอง)

ข้อผิดพลาดที่พบบ่อย
  • เข้าใจผิดว่า exec() สร้าง process ใหม่: จริง ๆ process ไม่ถูกโคลน PID ไม่เปลี่ยน มีแต่ program ที่รันอยู่ถูกแทนที่ (การสร้าง process คือ fork())
  • ลืมว่า function ที่ไม่มี p (execl, execv, execle, execve) ต้องระบุ exact path ของ program ไม่ค้นจาก PATH
  • เขียน exec ใน parent ทั้งที่ต้องการให้ shell ทำงานต่อ: ตามแนวคิด shell จะเรียก exec ใน child ที่ได้จาก fork เท่านั้น
มักออกสอบ
  • ลำดับการทำงานของ shell: Shell process → fork() → Child copy of shell → exec() → New program (ls, gcc, python)
  • หลัง exec: PID เดิมยังอยู่, Text เป็น program ใหม่, Heap reinitialized, Data/BSS ได้ค่าใหม่, Stack ได้ argv/env ใหม่ = same process, new program
  • ตีความชื่อ: execvp = ส่ง argument แบบ argv[] + ค้นหา program จาก PATH / execle = list + exact path + custom env
  • execve เป็น system call ตัวจริงของตระกูล exec
  • fork + exec ทำให้ shell เริ่มคำสั่งได้ในขณะที่ยังคุมระบบ (keep control) ไว้ได้

แบบทดสอบ

คัด 15 ข้อจากชุดเดิม 25 ข้อ: ปรนัย 10 ข้อ (ข้อ 1-10) + อัตนัย 5 ข้อ (ข้อ 11-15) ครอบคลุมทุกหัวข้อ กดตัวเลือกเพื่อตรวจคำตอบทันที ส่วนข้ออัตนัยกด "ดูเฉลย" เปิดดูเอง

1) Virtualization technology หมายถึงอะไร?

Virtualization technology อนุญาตให้สร้าง virtual version ของทรัพยากร เช่น server (สไลด์ OS LAB #1) ส่วนตัวเลือก C คือ dual-boot ซึ่งไม่ใช่ virtualization

2) ข้อใดคือ Bare-metal Hypervisor?

Bare-metal Hypervisor รันบนฮาร์ดแวร์ host โดยตรง ตัวอย่างคือ VMware ESXi และ Microsoft Hyper-V ส่วน VirtualBox และ VMware Workstation เป็น Hosted Hypervisor (รันบน OS ที่มีอยู่)

3) คำสั่งใดใช้ดูรายการ Linux distribution ที่ติดตั้งแล้ว พร้อมสถานะ (Running/Stopped) และเวอร์ชัน WSL (1/2)?

wsl -l -v (wsl --list --verbose) แสดง distro ที่ติดตั้งแล้ว + สถานะ + เวอร์ชัน WSL ส่วน wsl --list --online แสดงเฉพาะ distro ที่ติดตั้งได้จาก store

4) ข้อใดเป็นข้อดีสำคัญของ WSL 2 เมื่อเทียบกับ WSL 1?

WSL 2 มี Linux kernel จริง (built by Microsoft) ใน lightweight managed VM จึงได้ full system call compatibility และ file IO เร็วขึ้นมาก ส่วนการเข้าถึงไฟล์ Windows (ตัวเลือก A) กลับเป็น WSL 1 ที่เร็วกว่า

5) permission rwxr-xr-x เขียนเป็นเลข octal ได้เท่าใด?

r=4, w=2, x=1 → rwx = 4+2+1 = 7, r-x = 4+0+1 = 5, r-x = 5 รวมได้ 755 (ในสไลด์ยก rwxr-xr-x = 755 เป็นตัวอย่างตรง ๆ)

6) คำสั่งใดใช้ "เพิ่ม execute permission ให้ทุก user" กับไฟล์ myfile?

สไลด์ระบุ "To add execute permission for all users: chmod +x myfile" ส่วน chmod 777 คือการตั้ง rwx ให้ทุกคนทั้งชุด

7) คำสั่งใดใช้ออกจาก vi "โดยไม่บันทึก" การแก้ไข?

:q! = quit vi even though latest changes have not been saved (จากตาราง "To Exit vi") ส่วน :wq, :x, ZZ ล้วนบันทึกแล้วออก

8) คำสั่ง :%s/apple/pear/g ใน vi ทำอะไร?

% คือ address หมายถึงทั้งไฟล์ และ g ทำให้แทนที่ทุก occurrence ในบรรทัด จึงแทนที่ apple เป็น pear ทั้งไฟล์ (ตัวอย่างตรงจาก VI cheat sheet)

9) ความต่างของ Docker Image กับ Container ข้อใดถูกต้อง?

Docker Image = read-only template, immutable (แก้ไม่ได้ ต้อง build ใหม่) / Container = runnable instance ของ image และจาก image เดียวสร้าง container ได้หลายตัว

10) คำสั่ง docker run -d -p 8080:3000 nodejs-app หมายความว่าอะไร?

รูปแบบ -p คือ host:container จึง map port 8080 ของ host → port 3000 ของ container และ -d = detached (background) ตามตัวอย่างสไลด์ docker run -d -p 8080:3000 nodejs-app

11) (เขียนคำสั่ง) จงเขียนคำสั่งใน PowerShell (Run as administrator) เพื่อ: (1) ติดตั้ง WSL พร้อม Ubuntu และ (2) เปลี่ยน distribution ชื่อ Ubuntu-20.04 ให้ทำงานบน WSL 2

12) (เขียนคำสั่ง) จงเขียนลำดับคำสั่ง Linux เพื่อ: (1) สร้าง directory ชื่อ lab (2) สร้างไฟล์ชื่อ note.txt ข้างใน directory นั้น และ (3) ตั้ง permission ของ note.txt เป็น rwxr-xr-x (755)

mkdir สร้าง directory, touch สร้างไฟล์, chmod 755 ตั้ง permission rwxr-xr-x (owner rwx / group r-x / other r-x) : อนุญาตให้ใช้ chmod 755 lab/note.txt ระบุ path แทนการ cd ก็ถูกต้องเช่นกัน

13) (เขียนคำสั่ง) จงเขียนคำสั่ง Docker เพื่อ: (1) build image ชื่อ webapp จาก Dockerfile ใน directory ปัจจุบัน และ (2) รัน container จาก image นั้นแบบ background โดย map port 8080 ของเครื่องเราไปที่ port 3000 ของ container

docker build -t <ชื่อ> . อ่าน instruction จาก Dockerfile ใน directory ปัจจุบันแล้วตั้งชื่อ image / docker run -d รันแบบ detached, -p host:container map port (ตามตัวอย่างสไลด์ docker run -d -p 8080:3000 nodejs-app)

14) ใน vi ต้องการ copy บรรทัดปัจจุบันรวม 3 บรรทัด แล้วนำไปวางหลังบรรทัดปัจจุบัน จะกดคีย์อะไรอย่างไรบ้าง พร้อมอธิบายว่าถ้าวางผิดต้องการยกเลิกจะกดอะไร

ดูเฉลย

กด 3yy (yank/copy 3 บรรทัดนับจากบรรทัดปัจจุบันเข้า buffer) แล้วเลื่อน cursor ไปบรรทัดที่ต้องการ แล้วกด p (put/วาง buffer หลัง cursor/บรรทัดปัจจุบัน) : ถ้าวางผิดให้กด u เพื่อ undo สิ่งที่เพิ่งทำ (u = undo last change, เป็น simple toggle)

15) (trace ผลโค้ด exec/fork) กำหนดให้ shell ทำงานดังนี้ (แนวคิดตามสไลด์ exec() Family):

pid = fork();
if (pid == 0) {
    execvp("ls", args);   /* ใน child process */
}
/* parent: shell ยังทำงานต่อ */

จงตอบ: (ก) fork() สร้างอะไรขึ้นมา และ child process ที่ได้เป็นสำเนาของอะไร? (ข) เมื่อ child เรียก execvp("ls", args) PID ของ process จะเปลี่ยนหรือไม่ และอะไรบ้างที่ถูกแทนที่ใน process image? (ค) ชื่อ execvp บอกอะไรเกี่ยวกับวิธีส่ง argument และการค้นหา program? และเพราะเหตุใด shell (parent) จึงยังทำงานต่อได้หลัง exec?

ดูเฉลย

(ก) fork() สร้าง process ใหม่ โดย child เป็น copy ของ shell process (child copy of shell) : นี่คือการ "create a process" ที่ Unix แยกออกจากการ "run a different program"

(ข) PID ไม่เปลี่ยน : process ไม่ได้ถูกโคลนใหม่ (The process is not cloned) สิ่งที่เกิดคือ program ที่รันอยู่ถูกแทนที่: Text เปลี่ยนจาก program เดิมเป็น ls, Heap ถูก reinitialize, Data/BSS ได้ค่าใหม่, Stack ได้ argv/env ใหม่ → same process, new program

(ค) ตัว v = ส่ง argument แบบ vector/argv[] (array), ตัว p = ค้นหา program จาก PATH (ไม่ต้องระบุ exact path แบบ execv) / shell (parent) ยังทำงานต่อได้เพราะ exec ถูกเรียกใน child เท่านั้น : การออกแบบ fork()+exec() ทำให้ shell เริ่มคำสั่ง (เช่น ls, gcc, python) ได้ ในขณะที่ยังคุมระบบ/ทำงานต่อได้ (keep control) เพราะ program ที่ถูกแทนที่คือของ child ไม่ใช่ของ shell เอง
